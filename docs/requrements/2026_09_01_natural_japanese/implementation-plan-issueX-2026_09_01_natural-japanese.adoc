== 要件サマリ

`natural-japanese-rewriter` を、表面的な文字列整形ではなく述語項グラフの修復を中心にした親パイプラインへ強化する。
既存の `natural-japanese-rewrite-analyzer` を、述語ノード、指示対象ノード、項の辺、語義候補、ゼロ項、復元可能性を扱う前段分析へ拡張する。

親スキルは、語義と述語項構造を土台に、談話、情報構造、語用論、敬語、文体を順に分析する。
生成後は述語項グラフと、極性、モダリティ、発話行為などの意味不変条件を原文と比較する。
文書構造は構文上の妥当性だけでなく、原文と候補文の構造要素を対応付けて脱落や並べ替えを検出する。
原文へ戻す場合は依存する編集を原子的修復単位として扱い、復元後の候補文全体を再検証する。

対応する主要受け入れ条件は `AC-01` から `AC-15` である。
`AC-16` はパイプライン成果物全体の完了条件として Phase 6、Phase 9、Phase 10 で確認する。

== 技術方針

=== 既存 analyzer を拡張する

新規スキルは作らず、既存の分析子スキルを後方互換に拡張する。
親子の既存関係を維持し、同じ責務を持つスキルの重複と出力契約の二重管理を避ける。

=== 意味グラフと表層を分ける

表面の助詞、語順、態、項の明示または省略は、意味役割そのものと分ける。
リライト前後の比較では表面一致を要求せず、述語、指示対象、意味役割、極性、モダリティ、発話行為などの意味不変条件を使う。

=== 不確実性を保持する

語義、ゼロ項、指示表現を一意に決められない場合は、複数候補、`ambiguous`、`unknown` を保持する。
擬似的な数値確信度で確定したように見せず、復元可能性と判断根拠を使う。

=== progressive disclosure を維持する

通常の判断に必要なグラフ契約と安全制約は二つの `SKILL.md` に置く。
長文や既存の詳細例との照合が必要な場合だけ、既存 `references/detailed-rules.md` を読む。
新しい参照ファイルは、親と analyzer の間で必須契約を分散させるため追加しない。

=== 計画からの調整

実装中に、形容詞述語には態が適用されないことと、意味回帰で比較する時制・アスペクトが最小 YAML 契約に不足していることを検出した。
要件を先に更新し、`voice` へ `not-applicable` と `unknown` を追加し、`tense` と `aspect` を親子契約へ追加した。
これは既存の意味回帰要件を実装可能にする明確化であり、対象範囲の追加ではない。

公式 validator の Python 環境に PyYAML がなかったため、リポジトリへ依存を追加せず、`uv` の一時キャッシュで PyYAML を読み込んで実行した。

=== main 比較レビュー 1巡目

非対話の `codex review --uncommitted` で、P1 が2件、P2 が2件見つかった。

* analyzer 不在時に親だけで再現できる最小スキーマと列挙値を追加した。
* 翻訳調、冗長、過度に硬い表現、不自然な語順・助詞・重複を、安全に直せる場合の修復対象へ追加した。
* 意味回帰の比較項目へ敬語の方向を追加した。
* 短文でも最小出力契約のトップレベルキーを空配列として保持するよう明確化した。

4件とも要件の既存目的を実行可能にする修正であり、対象範囲は追加していない。

=== main 比較レビュー 2巡目

2巡目で、P1 が1件、P2 が2件見つかった。

* 項の実現形式から主題性を分離し、`discourse_role` で主題、主題継続、焦点、対比を表すよう変更した。
* 親の縮退スキーマへ entity レコードの `id`、`text`、`candidates` を追加した。
* `schema_version: 2` を追加し、旧 `verb`、`args`、`omitted_args` を正規フィールドから導出する互換ビューとして保持した。

これにより、`overt + topic` や `zero + topic-continuation` を同時に表現でき、analyzer がない環境と旧 predicate レコード利用者の移行契約を明確にした。

=== main 比較レビュー 3巡目

3巡目で P2 が2件見つかり、いずれも修正した。

* 親の縮退スキーマへ、問題コード9種、`predicate_ids`、`evidence`、`repairability` を持つ issue レコードを追加した。
* Phase 5 の意味回帰検査へ、Markdown / AsciiDoc の見出し階層、リストの入れ子、表、コードブロックを含む文書構造の妥当性を追加した。

3巡上限に達したため外部レビューの4巡目は行わず、修正後は validator、AsciiDoc 変換、HTML 契約、静的検査、`git diff --check`、差分の直接確認で回帰がないことを確認する。

=== Phase 10 の main 基準レビュー

最終 commit 後の `codex review --base main` で、P2 が1件見つかった。
旧 `args` と `omitted_args` の YAML 例が説明文字列になり、v1 の mapping / sequence 型を壊す指摘である。

`args: {}` と `omitted_args: []` に修正し、新 `arguments` から値を導出しながら旧コンテナ型を維持する規則を analyzer、親の縮退スキーマ、要件へ反映した。

同修正後の再レビューで P2 が3件見つかり、すべて要件を先に更新して修正した。

* analyzer 不在時も、親の縮退契約で正規フィールドから `verb`、`args`、`omitted_args` を導出する規則を明記した。
* 文書構造の構文妥当性だけでなく、原文と候補文の構造要素の数、順序、階層、対応関係を比較するよう変更した。
* 未解決箇所を原文へ戻すときは依存する編集を原子的修復単位として戻し、復元後の候補文全体を再検証するよう変更した。

同修正後の最終レビューで P1 が1件、P2 が1件見つかり、要件を先に更新して修正した。

* 語義候補、格フレーム、項スロットへ ID を付け、各項が対応する語義候補のフレームを参照するよう変更した。
* 旧 `omitted_args` には、指示対象を一意に復元できる `clear` のゼロ項だけを投影し、未解決のゼロ項を除外した。

独立フォワードテストで、複数の語義候補に同じ省略参加者が現れる場合の旧ビュー投影が一意でないことを検出した。
全投影元が同じ `legacy_label`、指示対象、実現形式に合意する項だけを1回記録し、候補間で競合する項は正規グラフと `ambiguities` に残す規則へ修正した。

== 移行、互換性、ロールバック

実行コード、外部依存、永続データを追加しないため、データ移行はない。
既存のスキル名、配置、通常出力、暗黙起動方針を維持する。

analyzer の内部契約は拡張されるが、既存キーを包含する。
外部利用者の有無は確認できないため、既存の単独分析用途を維持し、親専用にはしない。

問題発生時は、二つの `SKILL.md` をチェックポイント commit の内容へ戻し、派生 HTML を再生成する。
外部状態やデータの巻き戻しは不要である。
