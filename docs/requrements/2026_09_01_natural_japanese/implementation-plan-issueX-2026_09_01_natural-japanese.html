1. 計画の状態

Phase 9 のレビューガイドと3文書の HTML 生成まで完了した。 Phase 10 では、最終 commit、push、PR 本文の反映と再取得確認を行う。

2. 要件サマリ

natural-japanese-rewriter を、表面的な文字列整形ではなく述語項グラフの修復を中心にした親パイプラインへ強化する。 既存の natural-japanese-rewrite-analyzer を、述語ノード、指示対象ノード、項の辺、語義候補、ゼロ項、復元可能性を扱う前段分析へ拡張する。

親スキルは、語義と述語項構造を土台に、談話、情報構造、語用論、敬語、文体を順に分析する。 生成後は述語項グラフと、極性、モダリティ、発話行為などの意味不変条件を原文と比較する。

対応する主要受け入れ条件は AC-01 から AC-15 である。 AC-16 はパイプライン成果物全体の完了条件として Phase 6、Phase 9、Phase 10 で確認する。

3. 対象外

  • 外部 NLP 解析器、語義辞書、格フレーム辞書の追加

  • 実行時コードや永続データ構造の実装

  • references/detailed-rules.md 全体の再編

  • UI メタデータ、インストール手順、暗黙起動方針の変更

  • 原文の事実確認や不足する業務知識の推測

4. 技術方針

4.1. 既存 analyzer を拡張する

新規スキルは作らず、既存の分析子スキルを後方互換に拡張する。 親子の既存関係を維持し、同じ責務を持つスキルの重複と出力契約の二重管理を避ける。

4.2. 意味グラフと表層を分ける

表面の助詞、語順、態、項の明示または省略は、意味役割そのものと分ける。 リライト前後の比較では表面一致を要求せず、述語、指示対象、意味役割、極性、モダリティ、発話行為などの意味不変条件を使う。

4.3. 不確実性を保持する

語義、ゼロ項、指示表現を一意に決められない場合は、複数候補、ambiguous、unknown を保持する。 擬似的な数値確信度で確定したように見せず、復元可能性と判断根拠を使う。

4.4. progressive disclosure を維持する

通常の判断に必要なグラフ契約と安全制約は二つの SKILL.md に置く。 長文や既存の詳細例との照合が必要な場合だけ、既存 references/detailed-rules.md を読む。 新しい参照ファイルは、親と analyzer の間で必須契約を分散させるため追加しない。

9.3. 計画からの調整

実装中に、形容詞述語には態が適用されないことと、意味回帰で比較する時制・アスペクトが最小 YAML 契約に不足していることを検出した。 要件を先に更新し、voice へ not-applicable と unknown を追加し、tense と aspect を親子契約へ追加した。 これは既存の意味回帰要件を実装可能にする明確化であり、対象範囲の追加ではない。

公式 validator の Python 環境に PyYAML がなかったため、リポジトリへ依存を追加せず、uv の一時キャッシュで PyYAML を読み込んで実行した。

10. 移行、互換性、ロールバック

実行コード、外部依存、永続データを追加しないため、データ移行はない。 既存のスキル名、配置、通常出力、暗黙起動方針を維持する。

analyzer の内部契約は拡張されるが、既存キーを包含する。 外部利用者の有無は確認できないため、既存の単独分析用途を維持し、親専用にはしない。

問題発生時は、二つの SKILL.md をチェックポイント commit の内容へ戻し、派生 HTML を再生成する。 外部状態やデータの巻き戻しは不要である。
