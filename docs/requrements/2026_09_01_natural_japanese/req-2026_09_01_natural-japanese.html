1. 背景

現行の natural-japanese-rewriter は、原意・事実・仕様・技術的意味を保護しながら、述語、項、付加部、骨格を分析して日本語を整える。 ただし、述語ごとの項を平坦に列挙する現在の分析メモでは、複数述語が共有する項、主題化された項、ゼロ項、名詞化、態の交替、文をまたぐ指示対象を一貫して追跡しにくい。 そのため、表面的には自然でも、主体、対象、因果、可能性、発話意図などが原文からずれる余地がある。

本変更は、次の命題を基礎理論とする。

日本語推敲を文字列の整形ではなく、述語項グラフの修復として実装する。

ここでいう項は、述語の語義が意味を成立させるために用意する参加者スロットである。 日本語では項を自然に省略できるため、表面にないことと意味構造に存在しないことを区別する。

2. 目的

skills/natural-japanese-rewriter/SKILL.md を、次の処理を統括する親スキルへ強化する。

  1. 原文から語義、述語、項、指示対象のグラフを構築する。

  2. グラフ上の曖昧さや不整合を、原文にない情報を作らない範囲で修復する。

  3. 談話、情報構造、語用論、敬語、文体を意味構造の上に重ねてリライトする。

  4. 推敲前後の意味グラフを比較し、意味の回帰を検出する。

前段分析は、既存の skills/natural-japanese-rewrite-analyzer/SKILL.md を拡張して担わせる。 同じ責務を持つ新規スキルは作らない。

3. 利用者と利用シナリオ

主な利用者は、README、仕様書、技術記事、コードコメント、UI 文言、issue、PR 説明、業務連絡、職務経歴書などの日本語を推敲する Codex 利用者である。

代表的な利用シナリオは次のとおりである。

  • 省略された主語や目的語を、文脈から復元できる場合だけ明示する。

  • は や も で主題化された対象を、機械的に主語と誤認せずに整える。

  • 並列された述語が共有する主体や対象と、途中で切り替わる主体を区別する。

  • 顧客の確認 のような名詞化内部の動作主と対象の曖昧さを検出する。

  • 技術文書で、ブランチ、環境、入力、出力などの方向を保ったまま読みやすくする。

  • 可能性を断定へ、完了報告を許可要求へ変えるなどの意味回帰を防ぐ。

4. 用語

用語 定義 例

項構造

述語の語義が持つ意味的な参加者スロット

渡す〈渡し手, 物, 受取手〉

格フレーム

項スロットが助詞や構文として現れる候補

Xが Yを Zに 渡す

述語項構造

実際の文で、各スロットをどの指示対象が満たすか

田中さんが資料を顧客に渡した

述語項グラフ

述語ノード、指示対象ノード、項スロットを結ぶ辺、および極性・モダリティなどの意味属性からなる内部表現

二つの述語が同じ 担当者 ノードを共有する

ゼロ項

表面には現れないが、述語のスロットとして保持する項

文脈から復元できる 確認しました の確認者と確認対象

付加部

時、理由、条件、手段など、述語の語義が選択する項とは別に出来事を修飾する要素

昨日、本を読んだ の 昨日

項と付加部は、助詞や省略可能性だけで機械的に分類しない。 同じ表現でも、述語の語義によって項か付加部かが変わり得る。

5. 対象範囲

5.1. 対象

  • skills/natural-japanese-rewriter/SKILL.md の分析、修復、生成、意味回帰検査のパイプライン

  • skills/natural-japanese-rewrite-analyzer/SKILL.md の述語項グラフ分析手順と内部出力契約

  • 既存の references/detailed-rules.md へ到達する progressive disclosure

  • 通常のリライト出力と、ユーザーが分析を求めた場合の診断出力

5.2. 対象外

  • 外部の形態素解析器、係り受け解析器、語義辞書、格フレーム辞書の導入

  • TypeScript などによる実行時データ構造や NLP エンジンの実装

  • references/detailed-rules.md 全体の再編

  • UI メタデータ、インストール手順、スキルの起動条件の変更

  • 原文の事実確認や、原文に欠ける業務知識の推測

6. 機能要件

6.1. FR-01 入力、保護範囲、出力モードを確定する

親スキルは、処理開始時に対象範囲、出力先、文体、媒体を確定する。 コード、コマンド、ファイルパス、API 名、設定値、数値、固有名詞、引用、リンク、構造化データは、明確な誤りがない限り保護範囲として保持する。

既定の polish モードでは、修正後の本文を中心に出力する。 ユーザーが分析、理由、問題箇所を求めた場合だけ diagnostic モードとし、問題のある述語、不明または競合する項、修復した関係を簡潔に示す。

6.2. FR-02 述語項グラフを構築する

natural-japanese-rewrite-analyzer は、リライト前に次を行う。

  1. 動詞、形容詞述語、サ変名詞、出来事名詞、埋込み節の述語を抽出する。

  2. 同じ表記でも語義が複数あり得る場合は、語義候補、格フレーム候補、項スロットへそれぞれ ID を付けて保持する。

  3. 文中の同じ参加者を共有できる指示対象ノードとして登録する。

  4. 各述語の項スロットを指示対象ノードへ結び、表面にない項もゼロ項として保持する。

  5. ゼロ項の候補を、同一節、同一文の別述語、直前文、現在の主題、書き手、読み手、一般主体の順に探索する。

  6. 一意に決められない候補は確定せず、候補集合または unknown として保持する。

  7. 受け身、使役、可能、授受、敬語表現は、表面の助詞と意味役割を分けて扱う。

  8. は と も を自動的に主語とみなさず、主題化された項として判定する。

  9. 並列された述語について、項の共有と主体の切り替えを検査する。

  10. NのN、サ変名詞、出来事名詞、軽動詞について、動作主、対象、内容、結果の役割を検査する。

各項スロットでは、少なくとも次を別々に記録する。

  • 対応する語義候補 ID、格フレーム ID、項スロット ID

  • 述語の語義が選択する項、選択的斜格、付加部、判定不能の別

  • 表面の助詞または構文

  • 意味役割と、必要な場合のドメイン役割

  • 明示、ゼロ、関係節の空所、名詞化、一般主体、未解決の別

  • 主題、主題継続、焦点、対比などの談話上の役割

  • 指示対象または候補集合

  • 復元可能性 clear、probable、ambiguous、unknown

  • 判断根拠

数値の確信度を擬似的に精密化する必要はない。 復元可能性と根拠で、安全な補完可否を判断できることを優先する。

親子スキル間の最小出力契約は次の形とする。 配列が空の場合もキーを維持し、単独分析と親スキルの縮退実行で同じ用語を使う。

schema_version: 2
protected_ranges: []
rewrite_targets: []
entities:
  - id: entity-1
    text: 表面に現れた表現または null
    candidates: []
predicates:
  - id: predicate-1
    surface: 原文の述語
    verb: 原文の述語
    args: {}
    omitted_args: []
    lemma: 見出し語
    predicate_type: verb | adjective | verbal-noun | event-noun | embedded
    sense_candidates:
      - id: sense-1
        gloss: 語義候補
        case_frames:
          - id: frame-1
            slots:
              - id: slot-1
                role: 意味役割
                domain_role: ドメイン固有役割または null
                kind: core | selected-oblique | adjunct | uncertain
                legacy_label: 旧 args で使う単一ラベルまたは null
                surface_particles: []
    sense: sense-1 | unknown
    voice: active | passive | causative | causative-passive | potential | not-applicable | unknown
    polarity: positive | negative
    tense: 原文の時制または unknown
    aspect: 原文のアスペクトまたは unknown
    modality: {}
    arguments:
      - sense_id: sense-1
        frame_id: frame-1
        slot_id: slot-1
        role: 意味役割
        domain_role: ドメイン固有役割または null
        kind: core | selected-oblique | adjunct | uncertain
        surface: 原文の項または null
        surface_particle: 表面の助詞または null
        syntactic_relation: 統語関係または unknown
        realization: overt | zero | relative-gap | nominalized | generic | unresolved
        discourse_role: topic | topic-continuation | focus | contrast | none | unknown
        referent: entity-1 | null
        candidates: []
        recoverability: clear | probable | ambiguous | unknown
        evidence: 判断根拠
adjuncts: []
issues: []
ambiguities: []
graph_invariants: []
rewrite_policy: []

modality は、可能性、義務、許可、推量、断定の強さなど、原文に存在する属性だけを持つ。 graph_invariants は、リライト後にも保つ述語、指示対象、意味役割、極性、モダリティを列挙する。 surface と arguments を正規フィールドとする。 各 argument は sense_id、frame_id、slot_id で sense_candidates 内の一つの格フレームと項スロットを参照する。 複数の語義候補で格フレームが異なる場合は、項を語義候補ごとに分け、互換性のない役割を一つの argument へ統合しない。 verb、args、omitted_args は、analyzer 利用時と親スキルの縮退実行時のどちらでも正規フィールドから導出する互換ビューとする。 legacy_label は v1 の args と omitted_args へ投影するときの単一キーであり、表面助詞や語義別の意味役割を完全には表さない。 確定語義があればその格フレーム、確定していなければ残っているすべての語義候補と格フレームを投影元とする。 args は、各 legacy_label について、すべての投影元に同ラベルのスロットがあり、その項が同じ非 null の referent を指し、candidates に競合候補がない場合だけ、そのラベルと指示対象を1回記録する mapping とする。 omitted_args は、その合意に加えて、対応するすべての項が realization: zero と recoverability: clear を満たす場合だけ、同じラベルと指示対象を1回記録する sequence とする。 probable、ambiguous、unknown の項、または投影元の間でラベル、指示対象、実現形式が一致しない項は旧ビューへ含めず、正規の arguments と ambiguities に残す。 args と omitted_args は語義別の意味役割を落とす lossy view であり、意味判断には使用しない。 正規フィールドと互換ビューが矛盾する場合は正規フィールドを優先して矛盾を ambiguities に記録する。

6.3. FR-03 問題を分類する

分析時に、該当する問題を次のコードで記録する。

コード 意味

UNRESOLVED_CORE_ARGUMENT

重要な項の指示対象が不明

AMBIGUOUS_ANTECEDENT

ゼロ項や指示表現の候補が複数ある

CASE_FRAME_MISMATCH

表面の助詞や構文と述語の語義が整合しない

SUBJECT_DRIFT

並列述語または文間で主体が不明瞭に切り替わる

ATTACHMENT_AMBIGUITY

句が複数の述語へ係り得る

NOMINAL_ROLE_AMBIGUITY

名詞化内部の動作主、対象、内容、結果を区別できない

VAGUE_PREDICATE

する、なる、対応する、もの、こと などが意味関係を隠す

OVEREXPLICIT_ARGUMENT

復元可能な項が過剰に明示され、日本語として不自然または冗長

SEMANTIC_DRIFT

推敲後に述語、意味役割、指示対象、極性、モダリティなどが変化

6.4. FR-04 意味構造へ上位レイヤーを重ねる

親スキルは、下位から上位へ次の順で原文を分析する。

  1. 語彙意味論: 述語の語義候補

  2. 述語項構造: 誰が、何を、誰に、どこへ、どうしたか

  3. 談話構造: 指示表現、ゼロ項、現在の主題が何を指すか

  4. 情報構造: 原文の topic、focus、対比

  5. 語用論: 報告、依頼、質問、提案、謝罪、予定通知などの発話行為と requested action

  6. 対人関係: 書き手、読み手、第三者、敬語の方向、丁寧さ

  7. 文体: Slack、メール、技術文書などの媒体、簡潔さ、文末

不明な属性は推測で確定せず unknown とする。 項構造だけでは決められない情報構造、敬語、文体を独立したレイヤーとして扱う。

リライト候補は上位から下位へ制約を適用して生成する。 文体上の都合は、語義、項、指示関係、発話行為を変更してはならない。

6.5. FR-05 修復が必要な箇所だけを変更する

次のいずれかに該当し、かつ原文の情報だけで安全に改善できる場合に、項の明示、語順変更、助詞調整、具体化、文分割を行う。

  • 主体または対象に複数候補がある

  • 重要な項の指示対象が不明である

  • 助詞や構文が誤った意味役割を示す

  • 一つの句が複数の述語へ係り得る

  • 並列中の主体切り替えが不明瞭である

  • 名詞化によって動作主と対象を区別できない

  • 曖昧な述語や形式名詞が関係を隠す

  • 重要な項と述語が離れ、誤読が起こり得る

  • 意味関係は明確だが、翻訳調、冗長、過度に硬い表現、周囲と不整合な文体が読みやすさを損なう

  • 意味役割を変えずに直せる、不自然な語順、助詞、重複がある

次の場合は修復トリガーとせず、項を無理に補わない。

  • 書き手、読み手、直前の主題などから指示対象を一意に復元できる

  • 項が複数述語間で自然に共有されている

  • 省略しても誤読の可能性が低い

  • 明示すると不自然または冗長になる

  • 文体上自然な主題化や対比である

  • 問題のない原文である

安全に解消できない曖昧さは原文の表現を保持し、必要な場合だけ 要確認 へ記録する。

6.6. FR-06 リライトする

リライトは、述語項グラフと上位レイヤーを変更禁止の制約として行う。 語順、助詞、文分割、冗長表現、表現の硬さを整える場合も、保護範囲、原意、事実、仕様、技術的意味を保持する。

生成時の優先順位は次のとおりとする。

  1. 語義、指示対象、意味役割、極性、条件、因果、時系列、範囲、モダリティ

  2. 発話行為、requested action、情報構造

  3. 敬語の方向と対人関係

  4. 媒体に合う文体と自然さ

  5. 編集距離の小ささ

6.7. FR-07 意味回帰を検査する

推敲前後で述語項グラフを再構築し、意味的に比較する。 文字列、助詞、語順、項の明示または省略が一致する必要はないが、次の意味不変条件は一致しなければならない。

  • 述語の語義と出来事

  • 指示対象ノード

  • 項の意味役割とドメイン役割

  • 否定と肯定

  • 条件、例外、因果、時系列、範囲

  • 時制とアスペクト

  • 可能性、義務、許可、推量、断定の強さ

  • topic、focus、対比

  • 発話行為と requested action

  • 敬語の主体、方向、対人関係

  • 保護範囲

  • Markdown / AsciiDoc などの見出し、リスト項目、表の行、コードブロックについて、原文と候補文の要素数、順序、階層、入れ子、境界、対応関係が一致すること

不一致があれば SEMANTIC_DRIFT として候補を棄却し、修正して同じ検査を再実行する。 最大3巡で解消しない場合は、該当箇所だけでなく、文の分割・結合や共有指示対象で結び付く編集を含む最小の原子的修復単位を原文へ戻す。 原文へ戻した後の候補文全体へ Phase 1 と上位レイヤー分析を再実行し、意味不変条件と文書構造を原文ともう一度比較する。 不一致が残る場合は復元単位を段落または構造ブロックへ広げ、最終候補の不一致が0件になるまで出力へ進まない。 必要なら復元理由を 要確認 に加える。

6.8. FR-08 子スキルが利用できない場合に縮退する

natural-japanese-rewrite-analyzer が利用できない場合も、親スキルは同じ述語項グラフ出力契約に沿って分析を行う。 平坦な述語一覧だけで Phase を完了してはならない。 縮退実行でも surface と arguments を正規フィールドとし、verb、args、omitted_args を正規フィールドから導出する。 語義候補、格フレーム、項スロットの ID 参照と、全投影元に共通する項だけを旧ビューへ1回投影する条件も analyzer 利用時と同じにする。 正規フィールドと互換ビューの競合解消、コンテナ型、曖昧性の記録規則も analyzer 利用時と同じにする。 縮退した事実は最終報告へ含める。

7. 例外と失敗時の挙動

  • 入力または対象範囲を特定できない場合は、分析を開始せず対象を1件だけ確認する。

  • 語義候補を一つに確定できない場合は、複数候補を保持したまま、安全な候補に共通する修正だけを行う。

  • ゼロ項や指示表現の先行詞が競合する場合は、原文にない指示対象を作らない。

  • 発話行為や敬語の方向を確定できない場合は、原文の強さと敬語レベルを保持する。

  • 文書構造と意味保持が両立しない候補は採用せず、原文へ戻す。

  • 診断情報が長くなる場合も、既定の polish 出力へ内部分析全体を漏らさない。

8. 非機能要件

8.1. 意味安全性

原文にない主体、対象、原因、目的、時刻、確実性を追加しない。 技術用語を一般語へ薄めず、URL、コード、識別子、ブランチ名、PR 番号、メンションを変更しない。

8.2. 日本語としての自然さ

明示すると不自然な項は省略したままにする。 述語項グラフの構築を、すべての項を表面化する処理と誤解してはならない。

8.3. コンテキスト効率

1〜2文や UI 文言でも全 Phase の意味と最小出力契約のトップレベルキーは保つが、内部表現は必要なノードと辺だけに簡略化できる。 長文、複数述語、名詞化、技術的曖昧さを含む場合はグラフと上位レイヤーを省略しない。 既存の references/detailed-rules.md は、判断が難しい場合だけ読む。

8.4. 保守性

親スキルは層の順序、ゲート、失敗時挙動を統括し、子スキルは意味グラフ構築に集中する。 同じ指示を親子へ重複して長く記載せず、両者の入出力契約を一致させる。

9. 互換性、移行、運用

  • natural-japanese-rewriter と natural-japanese-rewrite-analyzer の名前、配置、暗黙起動方針は維持する。

  • 既存の polish 相当の通常出力は維持し、内部分析を既定で表示しない。

  • 既存 analyzer の protected_ranges、rewrite_targets、adjuncts、ambiguities、rewrite_policy は、拡張後も分析メモで表現できる状態を保つ。

  • 旧 predicate レコードの verb、args、omitted_args は、schema_version: 2 の正規フィールドから導出する lossy な互換ビューとして保持する。args は mapping、omitted_args は sequence の型を維持する。複数候補では全投影元が合意する項だけを重複なく投影し、判断時は正規の surface と arguments を優先する。

  • 実行コード、永続データ、外部依存を追加しないため、データ移行とロールバック作業は不要である。

  • 問題があれば、変更した二つの SKILL.md を直前版へ戻すことでロールバックできる。

10. 採用した意思決定

10.1. D-01 既存 analyzer を拡張する

自動壁打ちの推奨案として、述語項グラフ専用の新規スキルは作らず、既存 natural-japanese-rewrite-analyzer を拡張する。 前段分析という既存責務と一致し、子スキルの重複、起動競合、契約の二重管理を避けられるためである。

不確実性は、analyzer を単独利用している外部利用者の存在をリポジトリだけでは確認できない点である。 このため、既存の分析項目を包含する拡張契約とし、用途を狭めない。

10.2. D-02 グラフ同型性は意味上の等価性で判定する

推敲によって語順、助詞、態、明示と省略が変わること自体は許容する。 完全な表面一致では修復を妨げるため、述語、指示対象、意味役割、極性、モダリティ、発話行為などの意味不変条件で比較する。

10.3. D-03 擬似的な数値確信度を必須にしない

要件の根拠を説明できない数値は、安全な補完可否を明確にしない。 復元可能性の列挙値と判断根拠を必須とし、候補を一意にできない場合は ambiguous または unknown を保持する。

10.4. D-04 すべての層を分離し、必要な粒度で実行する

短文でも意味、発話行為、敬語、文体の順序は変えない。 ただし、該当情報がない層に空の詳細を量産せず、長文や曖昧な文では省略しない。

11. セキュリティとプライバシー

本変更は外部サービスへ文章を送信する処理や、認証情報を扱う処理を追加しない。 分析メモは原則として内部成果物とし、既定出力へ全文を露出しない。

12. 受け入れ条件

  • AC-01: 親スキルが、基礎理論を述語項グラフの修復として明記している。

  • AC-02: analyzer が、動詞以外に形容詞述語、サ変名詞、出来事名詞、埋込み述語を抽出対象にする。

  • AC-03: analyzer の出力契約で、述語ノード、指示対象ノード、項の辺、語義候補、語義ごとの格フレームと項スロット、復元可能性、根拠を ID で関連付けて表現できる。

  • AC-04: 表面の助詞、意味役割、主題、項の明示または省略を別々に扱う。

  • AC-05: ゼロ項を同一節、別述語、直前文、主題、書き手、読み手、一般主体から探索し、競合時に確定しない。

  • AC-06: 並列述語の項共有と主体切り替え、受け身、使役、可能、名詞化、軽動詞を検査する。

  • AC-07: 問題コード9種が定義され、修復判断または意味回帰検査に使われる。

  • AC-08: 談話、情報構造、語用論、敬語、文体が項構造とは別のレイヤーとして定義される。

  • AC-09: 修復トリガーと非トリガーが定義され、復元可能な自然な省略を維持する。

  • AC-10: 原文にない主体、原因、目的、時刻、確実性を作らない安全制約がある。

  • AC-11: 推敲前後で述語項グラフと非グラフの意味不変条件を比較し、文法的に妥当でも見出し、リスト項目、表の行、コードブロックの脱落・並べ替え・階層変更があれば SEMANTIC_DRIFT として扱う。

  • AC-12: 3巡で意味回帰を解消できない箇所は、依存する編集を含む原子的修復単位で原文へ戻し、候補文全体を再検証してから、必要なら 要確認 とする。

  • AC-13: 通常出力は本文中心のまま維持し、ユーザーが求めた場合だけ診断を出力する。

  • AC-14: analyzer と親スキルの縮退実行が同じグラフ契約を使い、正規フィールドから旧互換ビューを決定的に導出する。複数候補では全投影元が合意する項だけを1回記録し、omitted_args には一意に復元できるゼロ項だけを含める。

  • AC-15: 二つの SKILL.md が skill validator を通過し、frontmatter とスキル名を維持する。

  • AC-16: AsciiDoc 要件書、実装計画、レビューガイドと各 HTML が最新実装に一致する。

13. 検証シナリオ

ID 入力上の論点 期待する判定

T-01

このPRは確認しました。

このPR を確認対象の主題とし、主語へ誤分類しない

T-02

PRだけが直前の主題である文脈の 確認しました。

確認者と確認対象を zero / clear とし、不要に明示しない

T-03

担当者が内容を確認し、修正した。

二つの述語が担当者と内容を共有する候補を保持する

T-04

並列中に依頼先が現れ、修正主体が切り替わり得る文

SUBJECT_DRIFT または複数候補として扱い、主体を捏造しない

T-05

顧客の確認

確認者と確認対象の候補を分け、文脈で決まらなければ NOMINAL_ROLE_AMBIGUITY とする

T-06

dev環境のデータをCSVに取り込む

CSV が形式か到達点かを検査し、source、destination、format を混同しない

T-07

今後エラーが多発する可能性がある

推敲後も可能性を保持し、断定へ変えない

T-08

予定通知と異議連絡依頼を含む業務連絡

許可要求へ発話行為を変えない

T-09

自分と相手側人物の確認行為

確認主体を確定してから尊敬語または謙譲語の方向を判定する

T-10

URL、コード、ブランチ名、数値を含む技術文

保護範囲を変更せず、source と target の方向を保存する

T-11

語義またはゼロ項の候補が複数残る文

候補を一つに決めず、共通して安全な修正だけを行うか原文を保持する

T-12

analyzer を利用できない環境

親スキルが同じ最小出力契約で分析し、縮退した事実を報告する

T-13

縮退実行で arguments が設定され、空の args と omitted_args が併存する分析メモ

正規の surface と arguments を優先し、verb、args、omitted_args を導出して、競合を ambiguities に記録する

T-14

見出し、リスト項目、表の行を脱落または並べ替えた、構文上は妥当な候補文

原文との要素数、順序、階層、対応関係の不一致を SEMANTIC_DRIFT として検出する

T-15

文分割または文結合を含む修復の一部だけで意味回帰が解消しない候補文

依存する編集を含む原子的修復単位を原文へ戻し、候補文全体の意味と文書構造を再検証する

T-16

同じ表記の述語に、互いに異なる格フレームを持つ語義候補が複数残る文

各項を sense_id、frame_id、slot_id で対応する候補へ結び、互換性のない意味役割を統合しない

T-17

clear、ambiguous、unknown のゼロ項が混在する分析メモ

正規の arguments にはすべて保持し、旧 omitted_args には指示対象を一意に復元できる clear の項だけを投影する

T-18

複数の語義候補で同じ省略参加者が同じ旧ラベルへ対応し、別の項では候補間の役割または指示対象が競合する分析メモ

共通する (legacy_label, referent) は旧ビューへ1回だけ投影し、競合する項は投影せず ambiguities に残す

14. 品質確認方法

  • AsciiDoc の変換を実行し、構文警告と欠落がないことを確認する。

  • skill-creator の validator で、変更した各スキルの frontmatter、名前、未完了プレースホルダーを確認する。

  • 検証シナリオごとに、スキル指示から期待する分析と失敗時挙動を一意に説明できるかレビューする。

  • main との差分を最大3巡レビューし、重大または高重要度の未解決指摘を0件にする。

15. 未確定事項

外部 NLP 辞書を使わないため、語義と格フレーム候補の精度は実行するモデルと入力文脈に依存する。 ただし、複数候補と unknown を保持し、確定不能な情報を補わないことで安全側に実装できる。 実装を停止させる未確定事項はない。
