# nippo-only-update

日報 `~/develop/github.com.sogen/seiei-sogen/enterprise-agent-ssot/enterprises/ai-cross-memo/nippo/nippo.md`（なければ同じフォルダの `nippo.adoc`）を、Backlog と GitHub の情報で最新にする。
日報の書き方は拡張子によらず同じで、両方あるときは `nippo.md` を使う。
照合と書き換えは `scripts/nippo_only_update.py` が行う。

## 1. スクリプトを実行する

```sh
python3 "<このスキルのディレクトリ>/scripts/nippo_only_update.py" [日報のパス]
```

パスを省くと上の日報を書き換える。
書き換えたときは、前の内容を `<日報のファイル名>.bak`（`nippo.md.bak` など）に残し、標準出力に unified diff を出す。
最後に `== 報告`（足した課題、課題ごとの変更、足さなかった PR）と `== 失敗` が続く。

| 終了コード | 意味 | 次にやること |
| --- | --- | --- |
| 0 | 成功（変更なしを含む） | 手順2へ |
| 1 | 取得に失敗した課題やリポジトリがある。取れた分は書き換え済み | `== 失敗` の行を手順3で報告する |
| 2 | 日報がないか、Backlog の接続先がない | 止めて報告する |

Backlog の接続先は、環境変数 `BACKLOG_DOMAIN`・`BACKLOG_API_KEY`、なければ `~/.claude.json` にある backlog MCP の `env` から読む。

## 2. 差分を確かめる

スクリプトがすることは次のとおり。

- 最初に、自分（Backlog API キーの持ち主）が担当で、ステータスが「完了」以外の課題のうち、日報にないものを足す。探すのは、日報に載っている課題と同じプロジェクトだけ。親課題が `親子課題：KEY（子課題 N件）` の見出しにあればその節の末尾へ、なければ `個別の課題（N件）` の節の末尾へ、`- KEY 件名` と Backlog の URL を足し、見出しの件数を1増やす。足した課題にも、以下のステータス行・PR・ブランチが入る。
- Backlog の URL の次の行が、Backlog のステータス名そのもの（`設計中` など）か ` / ` 区切りなら、ステータス行とみなして `ステータス / 優先度 X / マイルストーン / 開始 M/D / 期限 M/D / 更新 M/D HH:MM`（更新は日本時間）で置き換える。それ以外の行は手書きのメモとして残し、その上にステータス行を入れる。値のない項目は省く。
- ブランチ名かタイトルが課題キーで始まる PR を、AICROSS の `REPOS` の各リポジトリから関連 PR とみなす。日報にない PR を `- チケット`・`- BE` などの見出しの下へ足し、見出しがなければ `REPOS` の順の位置に作る。マージせずに閉じた PR は足さない。
- ブランチがない PR の行に `- ブランチ` を足す。

次は変えない。

- `課題に紐づかないPR` など課題キーで始まらない塊
- すでに載っている行（完了した課題も、閉じた PR も消さない）

diff を読み、タイトルが課題キーで始まるだけの、本筋と違う PR（リリース用のデータ準備など）が足されていないかを見る。
不要なら、その3行を日報から消す。
全体を戻すときは `<日報のファイル名>.bak` で上書きする。

## 3. 報告する

足した課題と PR、変わったステータス、`== 報告` にある「足さない」と、`== 失敗` を伝える。

新しいリポジトリを追うときは、スクリプトの `REPOS` にリポジトリ名と見出しを足す。
スクリプトを変えたら、`python3 -m unittest "<このスキルのディレクトリ>/scripts/test_nippo_only_update.py"` が `OK` で終わることを確かめる。
