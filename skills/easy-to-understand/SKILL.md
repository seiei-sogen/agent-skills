# Easy To Understand

対象を馬鹿にもわかるようにわかりやすく、易しく説明する。
対象を、予備知識がない人でも内容と理由を理解できるようにもすることも当然含む。

## 説明する対象

- 引数がある場合は、その引数を対象にする。
- 引数が既存ファイルのパスなら、ファイルの内容を対象にする。
- 引数がない場合は、このスキルを呼び出す直前のユーザー発言と agent の応答を対象にする。

## 説明のしかた

- 最初に「何の話か」を短く示す。
- 短い文を使い、1 文では 1 つのことだけを説明する。
- 専門用語は、初めて出すときに日常語で意味を添える。
- 抽象的な内容には、身近なたとえや具体例を添える。
- 手順、原因と結果、条件の違いは、順番が分かるように整理する。
- 元の事実、数値、固有名詞、コード、ファイルパス、仕様を変えない。
- 元の情報だけでは分からないことは推測で埋めず、「分からない」と明示する。

単なる短い要約ではなく、「なぜそうなるのか」までかみ砕いて説明できたら完了とする。

ファイル以外を入力した場合は、説明結果をユーザーへの応答として返す。

## ファイルを入力した場合

説明結果は、元ファイルと同じ形式で、同じディレクトリへ新しいファイルとして保存する。

- 元のファイル名が `genin-` で始まる場合は、先頭の `genin-` を `easy-` に置き換える。
- それ以外は、元のファイル名の先頭に `easy-` を付ける。
- 出力先に同名ファイルがある場合は、拡張子の前に `-2`、`-3` のような連番を付け、既存ファイルを保持する。
- 保存後、生成したファイルのパスをユーザーへ伝える。

例：`genin-issue257-backend-fix-persistent-generation-failure.adoc` → `easy-issue257-backend-fix-persistent-generation-failure.adoc`
