# KWJA の解析結果を使う日本語リライト

日本語推敲を文字列の整形ではなく、述語項グラフの修復として実行する親スキルである。
KWJA の解析ファイルから述語、項、指示対象を読み取り、媒体に合う自然な日本語へ書き直す。

すべての省略項を表面化することが目的ではない。
省略したまま自然に読める項は、無理に表面化しない。

## 子スキルと優先順位

Phase 1 で [japanese-kwja-analyze](../japanese-kwja-analyze/SKILL.md) と [natural-japanese-rewrite-analyzer](../natural-japanese-rewrite-analyzer/SKILL.md) を読む。
前者が KWJA の解析ファイルを生成し、後者がその結果をリライト用の分析メモに整理する。
タイポ修正、分かち書き、単語正規化、形態素解析、固有表現認識、言語素性付与、係り受け解析、述語項構造解析、橋渡し照応解析、共参照解析、談話関係解析には KWJA の結果を使う。
LLM はその結果と原文を読み、自然さ、媒体、発話意図を判断して文章を生成する。

必要なスキルが見つからない場合や、KWJA の実行または解析ファイルの読み取りに失敗した場合は、リライトを止めて原因を報告する。
LLM による言語解析や規則の判定で代行せず、対象ファイルも編集しない。

指示が衝突する場合は、現在のユーザー指示、この親スキルのリライトモードと Phase 固有の指示、子スキルの通常指示の順に優先する。
デストロイモードで許容する意味の変更も、KWJA が出力した解析事実とは分けて扱う。

## 入力と出力モード

入力は、リライト対象の日本語テキスト、またはファイルパスとする。
第一引数が正確に `safe` の場合だけセーフモードとし、`safe` を対象テキストから除く。それ以外はデストロイモードとする。本文中の `safe` はモード指定として扱わない。
複数ファイルは1件ずつ独立したパイプラインとして扱う。
対象を特定できない場合は Phase 1 を始めず、対象を1件だけ確認する。

開始時に次を確定する。

- 対象範囲: 本文、見出し、箇条書き、コメント、UI 文言など
- 出力先: ファイル編集、応答本文、または本文を変更しない（レビューだけ、監査だけ）
- 媒体と文体: Slack、メール、技術文書、です・ます調、である調など
- 出力モード

出力モードは次の2つとする。

- `polish`: 既定。修正後の本文と `要確認` を出し、適用した規則の一覧や内部分析は出さない。`actionable` の数や文数に比例して出力を増やさない
- `diagnostic`: ユーザーが分析、理由、問題箇所を求めた場合だけ、本文に加えて問題のある述語、不明または競合する項、修復した関係、適用した規則 ID を簡潔に示す

「岩淵ルールで直して」「ルールID付きで推敲して」のように規則や ID を名指しする依頼と、適用した規則の提示を求める依頼は `diagnostic` として扱う。

本文を変更しない出力先（レビューだけ、監査だけ）では、Phase 1〜3 を通常どおり行い、Phase 3 の判定を最終とする。デストロイモードでも `needs-confirmation` を `actionable` に倒さない。Phase 4 は「レビューだけ」の修正案を作る生成方針としてだけ使い、Phase 5 は行わない。出力は `polish` / `diagnostic` の区別ではなく Phase 6 の「レビューだけ」「監査だけ」の規定に従い、`（LLM 判断）` もその規定で付ける。解析ファイルのパスは原文用だけを示す。

1〜2文や UI 文言でも Phase の順序と48規則の照合は変えず、`not-applicable` を素早く済ませて出力を増やさない。
分析メモの必須トップレベルキーは空配列でも保持し、必要なノードと制約だけに内部内容を簡略化できる。

## リライトの優先順位

デストロイモードでは意味保持より自然さを優先する。原文の語順や表現に引きずられず、文の分割・結合、構成の変更、語の置き換え、冗長な情報の削除を積極的に行う。自然な文章に必要なら、文脈からもっとも妥当な意味を選び、細部の意味の変化を許容する。問題のない文も、全体として自然になるなら書き直す。
48規則は自然さの判定基準として使い、`actionable` の判定と修正もこの許容の範囲で行う。`needs-confirmation` の箇所はもっとも自然な解釈を選んで `actionable` として扱ってよい。ただし、原文にない主体、対象、動作主、原因、目的、数値、時刻、確実性を確定させる解釈は選ばず、`needs-confirmation` のまま `要確認` に残す。`word-choice.match-expression-to-facts`、`sentence.state-changed-subject-explicitly`、`sentence.minimize-passive-voice` などがこれに該当する。

コード、コマンド、ファイルパス、API 名、設定値、数値、固有名詞、引用、リンク、構造化データは両モードで保護し、規則を理由に保護範囲を変えない。保護範囲にかかる箇所への規則の判定は `not-applicable` とし、保護範囲の外の箇所には同じ規則を通常どおり適用する。原文にない具体的な事実を作らない。

セーフモードでは次を守る。

- 原意、事実、仕様、技術的意味を変えない。
- 原文にない主体、対象、動作主、原因、目的、時刻、確実性を作らない。
- 否定、条件、例外、因果、時系列、範囲を変えない。
- 可能性、義務、許可、推量、断定の強さを変えない。
- 発話行為、相手に求める行動、敬語の方向を変えない。
- 技術用語を一般語へ薄めない。
- 問題のない文はそのまま残す。
- 規則を機械的に適用せず、読みやすさや正確さが実際に上がる変更だけを採用する。

自然さより意味保持を優先する。
判断材料が不足する場合は、文脈から一意に復元できる直しだけを行う。
一意に決まらない箇所は候補を保持し、安全な候補すべてに共通する変更だけを行う。
それでも誤解を避けられない場合は原文を保持し、必要なときだけ `要確認` とする。

規則どうしの判断が衝突した場合は、両モードとも次の順に優先する。デストロイモードでは自然さ最優先の方針を上位に置く。Phase 4 の優先順位は生成時の制約であり、この順序は規則どうしの衝突にだけ使う。

1. 原意・事実・仕様・技術的意味の保持
2. 文脈、係り受け、否定範囲、用語の正確さ
3. 読み手にとっての明確さ
4. 語感、敬語、簡潔さ
5. 行配置

## 岩淵48規則の ID 表

ID は安定した公開識別子として扱い、省略、改名、再利用せず、表にない ID を作らない。元メモの通し番号は使わない。

各規則の状態は次の4つとする。

- `pass`: その規則を適用でき、問題がない。
- `not-applicable`: 媒体、文体、文章の内容などから、その規則が対象外である。
- `actionable`: 規則に反する問題があり、原意を変えず安全に修正または修正提案できる。
- `needs-confirmation`: 問題または適用可能性を判断するには、原文にない情報やユーザーの意図が必要である。

上位概念は規則を判定する観測の層、出所は手がかりを得る場所である。`P1` は Phase 1 の分析メモと KWJA 出力、`P2` は Phase 2 で固定した上位レイヤーの制約、`P4` は Phase 4 の生成時の文書構造、`LLM` は KWJA 出力に直接の手がかりがなく原文と文脈から判断する規則を指す。

| ID | 規則 | 上位概念 | 主な手がかり | 出所 |

| `honorific.avoid-repeated-o-prefixes` | 同じ文章で「お」を過度に続けて使わない。 | 対人関係 | 同一文章内の「お」「ご」の出現密度 | P1 |
| `honorific.do-not-use-humble-forms-as-respectful` | 「お〜する」などの謙譲語を、尊敬語として誤用しない。 | 対人関係 | 謙譲形の述語と、その主体の `referent` が敬意の対象であること | P2 |
| `honorific.avoid-double-respectful-forms` | 尊敬語を二重に使わない。 | 対人関係 | 尊敬語形式の重複（形態素、活用） | P1 |
| `honorific.retain-required-forms` | 読み手、相手、場面に必要な敬語を落とさない。 | 対人関係 | 読み手、相手、場面と敬語レベル | P2 |
| `honorific.keep-forms-consistent` | 同じ文章内で敬語の形と敬意の向きを一貫させる。 | 対人関係 | 文章全体の敬語形式と敬意の向き | P2 |
| `honorific.avoid-mixing-polite-and-plain-styles` | 原則として「です・ます」調と「だ・である」調を混用しない。 | 文体 | 文末形式（です・ます / だ・である）の分布 | P2 |
| `honorific.allow-deliberate-style-mixing-for-effect` | 明確な効果を意図している場合だけ、文体の混用を認める。この規則は `honorific.avoid-mixing-polite-and-plain-styles` の例外とする。 | 文体 | 意図的な混用。`honorific.avoid-mixing-polite-and-plain-styles` の例外 | P2 |

## Phase 1: KWJA の解析ファイルから分析メモを作る

`natural-japanese-rewrite-analyzer` に原文と対象範囲を渡す。
同スキルの手順で `japanese-kwja-analyze` を実行し、生成された `.kwja.txt` を入力に分析メモを作る。
解析用テキストの準備、原文との対応付け、KNP の読み取り、分析メモのスキーマは同スキルの契約に従う。

生成へ進む前に `analysis_source.input_file` と `analysis_source.result_file` の実ファイルを読み、対象範囲の全文が処理されたことを確認する。
長い解析結果は文 ID を保持して分割して読み、文をまたぐ照応と談話関係も追う。
コマンドの成功やファイルパスの取得だけで分析完了としない。
同じ実行内で内容が変わっていない入力の解析結果は再利用し、親スキルから重複実行しない。

KWJA にない語義、項、関係は `unknown` または曖昧さとして残す。
デストロイモードでは `graph_invariants` と `rewrite_policy` を原文の分析資料として扱い、書き直しの制限にはしない。

完了条件: 対象テキストに対応する KWJA の解析ファイルを読み終え、子スキルの出力契約を満たす分析メモがあり、各判断を原文と解析ファイルへたどれる。

## Phase 2: 上位レイヤーの制約を固定する

Phase 1 の意味グラフを土台に、下位から上位へ次を分析する。

1. 談話構造
   - 指示語とゼロ項の候補
   - 現在の主題と文間の主体・対象の継続
2. 情報構造
   - 原文の topic、focus、対比
   - `は`、`が`、`も` を変えたときの焦点の変化
3. 語用論
   - 報告、依頼、質問、提案、謝罪、予定通知、警告などの発話行為
   - 読み手へ求める行動
4. 対人関係
   - 書き手、読み手、第三者
   - 尊敬語、謙譲語、丁寧語の主体と方向
5. 文体
   - 媒体、文末、簡潔さ、丁寧さ

不明な属性は `unknown` とする。デストロイモードでは自然な表現に必要な解釈を選べる。セーフモードでは文体の都合で下位レイヤーの語義、指示関係、発話行為を変更してはならない。
選んだ解釈は生成方針に記録し、KWJA の解析結果や未出力の項を補うためには使わない。

完了条件: 原文に存在する topic / focus、発話行為、requested action、敬語の方向、文体が、保持する制約または `unknown` として整理されている。

## Phase 3: 修復箇所を決める

次に該当する箇所を修復対象にする。セーフモードでは原文の情報だけで安全に改善できる箇所に限る。
デストロイモードでは原文全体を書き直しの対象とし、問題のない文も自然さのために変更できる。

- 主体または対象に複数候補があり、文脈で安全に絞れる
- 重要な項の指示対象が不明で、原文内の明示で解消できる
- 助詞や構文が誤った意味役割を示す
- 一つの句が複数の述語へ係り得る
- 並列中の主体切り替えが不明瞭である
- 名詞化によって動作主と対象を区別できない
- `する`、`なる`、`対応する`、`もの`、`こと` などが意味関係を隠す
- 重要な項と述語が離れ、誤読が起こり得る
- 意味関係は明確だが、翻訳調、冗長、過度に硬い表現、周囲と不整合な文体が読みやすさを損なう
- 意味役割を変えずに直せる、不自然な語順、助詞、重複がある

次の場合は項を無理に補わない。

- 書き手、読み手、直前の主題から一意に復元できる
- 項が複数述語間で自然に共有されている
- 省略しても誤読の可能性が低い
- 明示すると不自然または冗長になる
- 文体上自然な主題化や対比である
- セーフモードで原文に問題がない

48規則をすべて照合し、各 ID を4状態のいずれかにする。判定の材料は ID 表の出所に従う。`P4` の `output.line-break-each-line` は、改行単位の指定の有無から状態をここで決め、Phase 4 の生成時に規則本文のとおり適用する。
出所が `P1` でも、手がかりとなる素性やタグが KWJA 出力にない規則は `LLM` 出所として原文から判定し、その旨を記録する。素性がないことを理由に `not-applicable` としない。`LLM` 出所の判定は `rewrite_targets` の要素に `source: llm` として記録し、`predicates`、`arguments`、`entities`、`issues`、`ambiguities` には KWJA 出力にない根拠を書き込まない。

Phase 3 でこの親スキルが分析メモの `rewrite_targets` に要素を追記する。各要素は、少なくとも `decision`（`repair` / `keep` / `confirm`）、`rule_ids`、`source`（`kwja` / `llm`）を持つ。`rule_ids` は主 ID を先頭に置いて関連 ID を続け、空配列でもよい。上の修復一覧で選んだ箇所にも該当 ID を付ける。`actionable` は `repair`、`needs-confirmation` は `confirm`、「補わない」一覧に当たる箇所など意図的に残す箇所は `keep` とする。`keep` の箇所に付けた規則の状態は `pass` とする。規則違反がない自然さ目的の書き直しも `decision: repair`、`rule_ids: []` で記録する。本文を変更しない出力先では `repair` は修正案の提示を意味し、`rule_ids: []` の書き直しは記録しない。`confirm` は Phase 6 の `要確認` に ID 付きで出し、本文を変更しない出力先では監査一覧または判定行に含める。規則に対応しない `confirm`（`rule_ids: []`）は、判定行では ID 欄を `-` とし、監査一覧では表の直後に ID なしで1行ずつ添える。`pass` と `not-applicable` は記録するだけで、監査一覧を除き出力しない。

長文、複数述語、名詞化、技術的曖昧さを扱う場合や、既存ルールとの照合が必要な場合は、ここで `references/detailed-rules.md` を読む。
セーフモードでは、分析メモの `ambiguities` に当たる箇所を「リライトの優先順位」の順序（一意に復元できる直し、安全な候補すべてに共通する変更、原文保持）で扱い、それでも確定できない箇所（`repairability: blocked`、`recoverability: unknown` など）は `actionable` にせず `needs-confirmation` として原文を保持する。この判定は上の修復トリガーより優先する。

完了条件: `rewrite_targets` の各要素の `decision` が `repair`、`keep`、`confirm` のいずれかになっている。48個の ID すべてに状態が付き、`actionable` と `needs-confirmation` が `rewrite_targets` に `rule_ids` 付きで記録されている。セーフモードでは修復理由と変更禁止の制約も対応している。

## Phase 4: 制約に沿って生成する

分析結果を参照し、語順、助詞、文分割、冗長表現、硬さを整える。セーフモードでは上位レイヤーから下位レイヤーへ制約を適用する。
デストロイモードでは、媒体に合う自然さを最優先する。原文の細部や編集距離を維持するために不自然な表現を残さない。

セーフモードの優先順位は次のとおりとする。

1. 語義、指示対象、意味役割、極性、条件、因果、時系列、範囲、モダリティ
2. 発話行為、requested action、topic、focus、対比
3. 敬語の主体、方向、対人関係
4. 媒体に合う文体と自然さ
5. 編集距離の小ささ

Markdown の見出し、箇条書き、表、コードブロック、JSON / YAML / TOML、コマンド例などの構造を壊さない。

完了条件: 修復対象が処理され、両モード共通の保護範囲が保持されている。セーフモードでは変更禁止の制約も保持されている。

## Phase 5: 候補文を検査する

両モードで、候補文に48規則を再照合し、新たな `actionable` を作っていないことを確認する。デストロイモードは候補文を再解析しないため `LLM` 出所で判定し、セーフモードは下の意味回帰検査で再解析した分析メモを使う。新たな `actionable` が見つかった場合は、候補を修正して再照合する。再照合は最大3巡とする。解消しない `actionable` は `needs-confirmation` に変え、原文用の分析メモの `rewrite_targets` に `confirm` として追記して `要確認` に出す。再照合で新たに検出して修正した項目も同じ `rewrite_targets` に `repair` として追記し、`diagnostic` の適用ルールに載せる。

デストロイモードでは候補文の自然さと読みやすさを確認する。両モード共通の保護範囲、原文にない具体的な事実の混入、文書構造の破損を確認し、見つけた問題を直す。以下の意味回帰検査は行わない。

セーフモードでは次の意味回帰検査を行う。

候補文を原文用とは別の作業ファイルへ保存し、Phase 1 と Phase 2 を再実行する。
候補文用の KWJA 解析ファイルを新たに生成して読み、原文用の解析ファイルを残したまま比較する。
候補文を再修正した場合も、更新後の内容を KWJA で再解析する。
文 ID や基本句 ID は解析ごとに付け直されるため、ID の一致ではなく、原文と候補文の対応箇所、指示対象、意味役割を照合する。
タイポ修正・正規化後の解析表記だけで意味保持を判断せず、修正前の原文と候補文も直接比較する。
KWJA の予測と本文が食い違う箇所や対応を確定できない箇所は、検査合格にせず `要確認` とする。
ただし、原文用の解析の対応箇所にも同じ誤予測（関係の種類と、誤った係り先・参照先が同じもの）がある場合は、書き換えで生じた差ではないため、分析メモの `ambiguities` に記録するだけで不一致にも `要確認` にもしない。
語順、助詞、態、項の明示または省略は一致しなくてもよいが、次は一致しなければならない。

- 述語の語義と出来事
- 指示対象と項の意味役割、ドメイン役割
- 否定、条件、例外、因果、時系列、範囲
- 時制、アスペクト、モダリティ、断定の強さ
- topic、focus、対比
- 発話行為と requested action
- 敬語の主体、方向、対人関係
- 保護範囲
- Markdown / AsciiDoc などの見出し、リスト項目、表の行、コードブロックについて、原文と候補文の要素数、順序、階層、入れ子、境界、対応関係

不一致は `SEMANTIC_DRIFT` として候補を棄却し、修正して同じ検査を再実行する。
最大3巡で解消しない場合は、文の分割・結合や共有指示対象で結び付く編集を含む最小の原子的修復単位を原文へ戻す。
原文へ戻した後の候補文全体へ Phase 1 と Phase 2 を再実行し、意味不変条件と文書構造をもう一度比較する。
不一致が残る場合は復元単位を段落または構造ブロックへ広げ、同じ再検査を行う。

完了条件: 候補文で `actionable` の規則が0件であり、最終候補全体で意味不変条件（セーフモード）と文書構造の不一致が0件であり、必要な `要確認` が記録されている。原文へ戻したことだけを不一致解消の根拠にしない。

## Phase 6: 出力する

ファイルが対象なら修正を反映し、本文を再掲せず、変更ファイル、変更概要、`要確認` を短く報告する。セーフモードでは必要最小限の変更にとどめる。
応答本文が対象なら修正後の本文を先に出し、必要な場合だけ `要確認` を続ける。

`要確認` の各項目は ``- `{ID}`: {原文だけでは判断できない点}`` の形にする。規則に対応しない `要確認`（KWJA と本文の食い違いなど）は ID なしで出す。

`diagnostic` モードでは、次を簡潔に追加する。

1. 問題のある述語
2. 不明または競合していた項
3. 修復で明確になった関係
4. 適用ルール。``- `{ID}`: {対象箇所と修正内容}`` の形で書き、`actionable` がなければ「適用ルール: なし」と書く

`diagnostic` では、`LLM` 出所の判定（素性がないため `P1` から `LLM` に切り替えたものを含む）に、適用ルールと `要確認` の行末で `（LLM 判断）` を付ける。`polish` の `要確認` では付けない。本文を変更しない出力先では、判定行と監査一覧の規定に従う。

監査結果または全規則の判定を求められた場合だけ、規則の定義順に48行の監査一覧を出す。監査だけを求められた場合は本文を変更せず、監査一覧と解析ファイルのパスだけを出す（ID 付き `要確認` の別掲と診断は出さない）。監査と推敲の両方を求められた場合は `diagnostic` として扱い、監査一覧をその末尾に加える。ID が複数箇所で異なる状態になる場合、監査一覧の状態は `needs-confirmation`、`actionable`、`pass`、`not-applicable` の順で強いものを1つ書き、3列目に箇所ごとの内訳を書く。規則の判定を完了できない場合（Phase 3 前の停止など）は部分的な一覧を出さず、停止理由を報告する。

```markdown
| ID | status | 根拠または対象箇所 |
|---|---|---|
| `{ID}` | `pass / not-applicable / actionable / needs-confirmation` | {短い根拠、対象箇所、判断に必要な情報。LLM 判断ならその旨} |
```

「レビューだけ」「直さないで」の場合は本文を変更せず、`actionable` と `needs-confirmation` の判定を `rewrite_targets` の要素ごとに1行の `ID / 対象箇所 / 問題 / 修正案` の形で出し、解析ファイルのパスを添える（ID 欄には `rule_ids` を並べる）。診断の他の項目と `要確認` の別掲は出さず、修正案は Phase 4 の生成方針で作る。`needs-confirmation` は修正案の代わりに判断に必要な情報を示し、`LLM` 出所の行は末尾に `（LLM 判断）` を付ける。
「最終版だけ」の場合は適用ルール、診断、解析ファイルのパスを省く。`要確認` は省略しない。

分析メモ全体、内部手順、問題のない箇所の説明は出さない。
使用した KWJA 解析ファイルのパスを短く示す。セーフモードで Phase 5 の意味回帰検査を行った場合は、原文用と最終候補用の両方を示す。

出力先に応じてリライト本文、判定、または監査一覧が出力され、両モード共通の保護範囲と文書構造が保持され、`要確認` がすべて報告済みなら完了とする。
