# 述語項グラフによる日本語リライト前分析

日本語推敲を文字列の整形ではなく、述語項グラフの修復として扱うための前段分析スキルである。
述語を個別に列挙するだけでなく、同じ参加者を指す項、表面にないゼロ項、語義候補を文全体で関連づける。

このスキルは原則としてリライトしない。
`natural-japanese-rewriter` の前段では分析メモを内部入力として渡し、ユーザーが分析だけを求めた場合は問題と不確実性を簡潔に出力する。

## 解析元

[japanese-kwja-analyze](../japanese-kwja-analyze/SKILL.md) を読み、生成された KNP 形式の `.kwja.txt` を解析元にする。
分析メモの KWJA 由来部分は [scripts/build_memo.py](scripts/build_memo.py) が `.kwja.txt` から作る。LLM はこの部分を書かない。
同じ実行内で、現在の入力と内容が一致する解析用テキスト、解析ファイル、分析メモが渡された場合は、それらを読み取って再利用する。
それ以外は KWJA とスクリプトを実行する。過去のファイルを名前だけで再利用しない。
実行や読み取りに失敗した場合は分析を止め、原因を報告する。LLM による形態素解析、係り受け解析、項・照応関係の推測で代行しない。

KWJA の結果はモデルの予測として扱う。本文との矛盾は `ambiguities` に記録する。
KWJA が出力していない関係は未検出として残し、存在しないことの証明にはしない。
LLM が判断する修復案、語用論、文体と、KWJA の出力にある解析情報を区別する。

## 分析手順

### 1. 原文と解析用テキストを対応付ける

対象の日本語本文、見出し、箇条書き、コメント、UI 文言を確定する。
コード、コマンド、構造化データ、URL、ファイルパス、API 名、設定値、数値、固有名詞、引用などの保護範囲は、修正前の原文から記録する。

プレーンテキストのファイル全体が対象なら、そのファイルを KWJA に渡す。
Markdown、AsciiDoc、コードなどの一部が対象なら、対象の文章を出現順に抽出した UTF-8 の作業用 `.txt` を原文と同じディレクトリに作る。
文をまたぐ関係を解析できるよう、文脈と段落の順序を保ち、文ごとに独立実行しない。
KWJA は改行を削除してから句点などで文を区切るため、改行や空行は文の境界にならない。
見出し、箇条書きの項目、表のセル、UI 文言など、句点や `？`、`！` で終わらない単位は、次の単位と1文につながらないよう末尾に `。` を補う。
補った `。` は原文にないため `source_alignment` で区別し、原文の編集位置に含めない。
応答本文などファイルのない入力も、作業ディレクトリにテキストファイルとして保存する。
作業ファイルは既存ファイルと衝突しない名前にし、原文用と候補文用を別々にする。

抽出した箇所と原文の行・範囲の対応を `source_alignment` に記録する。
タイポ修正・単語正規化によって表記や長さが変わるため、解析結果の文字位置をそのまま原文の編集位置にしない。

### 2. KWJA を実行し、分析メモを生成する

`japanese-kwja-analyze` のスクリプトへ解析用テキストのパスを渡し、同スキルの完了条件を確認する。
続けて、このスキルのディレクトリを基準に次を実行する。

```bash
uv run "<このスキルのディレクトリ>/scripts/build_memo.py" "<解析用テキストの絶対パス>" "<.kwja.txt の絶対パス>"
```

スクリプトは `<解析用テキスト>.memo.yaml` を書き、保存先を標準出力に返す。
このファイルの全文を読む。`.kwja.txt` は全文を読まず、メモにない形態素の品詞や読みを確かめる場合だけ、該当する文を検索して読む。
元の KNP ファイルは加工せず残す。

### 3. 分析メモを読む

スクリプトが作る部分は次のとおり。この部分は編集しない。

| キー | 内容 |
| --- | --- |
| `analysis_source` | 解析用テキストと解析ファイルのパス |
| `sentences[].text` | KWJA が区切った文。タイポ修正・正規化後の表記 |
| `sentences[].phrases` | 基本句ごとの1行。`番号>係り先番号+係り種別 表層 \| 素性`。係り種別は `D`（通常）、`P`（並列）、`A`（同格）、`I`（部分並列）。係り先 `-1` は文末 |
| `sentences[].predicates[].attrs` | 述語の `id`、`surface`、`type`（`verb` / `adjective` / `copula` / `event-noun`）。該当する場合だけ `polarity: negative`、`tense`、`voice_hint` |
| `sentences[].predicates[].arguments` | 項。`role` は KWJA の格。`at` は参照先の `文番号/基本句番号`、`entity` は共参照でつながる場合の ID |
| `entities` | 共参照でつながる基本句の集まり |
| `bridging` | 橋渡し照応（ノ格の関係） |
| `discourse` | 談話関係。`参照先の文番号/基本句番号/関係` |

項の `realization` は、係り受けと関係タグから次のように決まる。

- `overt`: 項が同じ文で述語に係る。`particle` は項の基本句の最後の助詞
- `relative-gap`: 述語が項に係る（連体修飾の被修飾語）
- `zero`: それ以外。`referent: 外界:…` は外界照応で、文書内の位置を持たない

`overt` 以外の項の `recoverability` は、KWJA が同じ格に先行詞を1つ出力すれば `clear`、複数なら `ambiguous` になる。
`voice_hint` は接尾辞「れる・られる」「せる・させる」の有無だけを示す。受身か可能かは本文で判断する。
`phrases` には、行数の多い素性（`体言`、`動態述語`、`状態述語`、`節-主辞`、`レベル`）と形態素ごとの品詞・読みを載せていない。必要なら `.kwja.txt` で確かめる。
KWJA が出力していない語義、格フレーム、項はメモにない。LLM の知識から追加しない。

### 4. 原文と照合して LLM が埋める部分を書く

メモの末尾にある次のキーを、原文と上の解析結果を照合して埋める。該当がなければ空配列のまま残す。

| キー | 内容 |
| --- | --- |
| `source_alignment` | 抽出した箇所と原文の行・範囲の対応。補った `。` を区別する |
| `protected_ranges` | 修正前の原文から記録した保護範囲 |
| `rewrite_targets` | 親スキルが Phase 3 で追記する |
| `issues` | `code`（問題コード）、`predicate_ids`、`evidence`、`repairability`（`safe` / `contextual` / `blocked`） |
| `ambiguities` | KWJA の予測と本文の矛盾、対応が不明な箇所。該当する述語 ID または `文番号/基本句番号` を添える |
| `graph_invariants` | 書き換えても変えてはならない関係 |
| `rewrite_policy` | 修復案。確定不能な情報の補完を指示しない |

項共有、主体切り替え、態、名詞化、軽動詞、曖昧な係り受けを確認する。
KWJA の予測が本文と矛盾する項（先行詞が文意に合わない、本文で明示された項を別の先行詞に結んでいる、など）は、スクリプトの出力を書き換えず `ambiguities` に記録する。`ambiguities` にある項は、`recoverability: clear` でも一意に復元できる項として扱わない。
親スキルのデストロイモードで別の解釈を選ぶ場合も、生成時の判断として扱い、KWJA の解析結果を書き換えない。
`.memo.yaml` を編集した後にスクリプトを同じ入力へ再実行しない。再実行は LLM が埋めた部分を上書きする。

## 完了条件

次のすべてを満たした場合だけ分析完了とする。

- 対象範囲の全文に対応する `.memo.yaml` をスクリプトで生成し、全文を読んでいる。
- スクリプトが作った部分を編集しておらず、未出力の項や関係を補っていない。
- 原文・解析用テキスト・解析結果の対応を確認し、不明な箇所を記録している。
- 複数述語の共有項と主体切り替えを検査している。
- 保護範囲、問題、曖昧さ、意味不変条件が記録されている。
- 原文にない情報を確定していない。

単独利用では、分析メモ全体を機械的に表示する必要はない。
問題のある述語、競合または不明な項、判断根拠を、ユーザーの求める粒度で提示する。
