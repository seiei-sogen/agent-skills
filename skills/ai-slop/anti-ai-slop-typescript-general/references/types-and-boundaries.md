# 型と境界

差分で型、バリデーション、ガード、型アサーション、型変換、オプショナルな値、外部データの処理を変更している場合に、このリファレンスを使う。

## 信頼境界から確認する

HTTP リクエスト、Webhook、キューメッセージ、外部 API、環境変数、生の JSON、ユーザー入力、型が緩いデータベース結果は、信頼できない値として扱う。プロジェクトで採用済みのスキーマライブラリを使って境界で一度だけ検証し、正確な型にして内部へ渡す。

型付けされたアプリケーションコードが生成した値は、契約や実行時の入力元から信頼できないと分かる場合を除き、その型を信頼する。不正確な入力元の型を修正し、各利用箇所で型を何度も判定し直さない。

## 次の置き換えを検討する

| 兆候 | 優先する実装 | 元の実装を残す条件 |
| --- | --- | --- |
| ビジネスロジック内の `unknown`、`any`、`Record<string, unknown>` | 境界で確定した具体的なドメイン型 | その関数自体が解析境界である |
| `typeof`、`in`、`instanceof` の繰り返し | 1回のスキーマ解析または入力元の型修正 | 実行時の入力が本当に複数の型を取り得る |
| 最後に `as T` を使うガード | 実際のスキーマ検証、または外部契約に裏付けられた明示的で局所的な型アサーション | 文書化された保証を最も狭く明確に表せるのが型アサーションである |
| 既知の1つの構造を扱う `asX`、`isX`、`safeX`、`extractX`、`normalizeX` | 型付けされた値への直接アクセス | ヘルパーが再利用されるドメイン上の不変条件を表す |
| `Partial<LargeType>` | 実際に受け入れるフィールドだけを持つ小さな型 | 部分更新が本当にすべてのフィールドを受け入れる |
| `string | null | undefined` | 契約で必要な1種類の欠損状態 | 各状態に異なる観測可能な意味がある |
| 防御目的で追加されたオプショナルフィールド | ドメイン上必須なら必須フィールド | 欠損が実際にサポートされる状態である |
| キーが既知の `Record<string, Handler>` | `Record<EventName, Handler>` または型付きオブジェクト | キーが本当に任意である |
| `event: string` と `data: unknown` を持つキューのペイロード | 判別可能なユニオン | イベントが型システム外から動的に登録される |
| 重複する request、DTO、model、response の構造 | 1つの共有構造 | 契約の意味、公開範囲、ライフサイクルが異なる |

## バリデーションと型変換を分ける

型変換はバリデーションではない。`String(value)`、`Number(value)`、`Boolean(value)`、テンプレートリテラルへの埋め込み、`!!value` は、不正なデータを一見正しいデータへ変えることがある。

型が正しい値だけを正規化する。ユーザーが入力したドメイン文字列を trim して小文字にするのは意味がある。数値をドメインとして受け入れ、文字列へ変換するのは正規化ではない。

`value ?? ""`、`value ?? {}`、`value ?? []`、早期の `return undefined` などの空フォールバックは、サポートされるドメイン状態を表す場合だけ使う。必須データがない場合は、空の値を捏造せず、リポジトリで定められた通常の失敗として扱う。

## 実装全体が簡潔になる場合にスキーマを使う

プロジェクトで採用済みの Zod、Valibot、Yup、Joi、TypeBox、Ajv などのスキーマを再利用または合成する。ライブラリが対応している場合は、同じ契約から TypeScript の型を導出する。

実装を比較するときは、依存関係のコスト、重複するスキーマ、エラー変換も含める。信頼済みの内部コードが長くなるスキーマは採用しない。

## 永続化データの型を具体的にする

Mongo、Mongoose、ORM、データベース結果の型を、永続化スキーマと一致させる。フィールドが `ObjectId` であることを保証できるなら、その型として表現し、必要な操作を直接呼び出す。複数形式が混在するデータ、移行中のデータ、nullable なデータ、外部から投入されるデータが公称型に違反し得る場合は、実行時チェックを残す。

## 完了条件

変更経路にある広い型をすべて、アプリケーションへ入る地点までたどる。各型が境界で一度だけ絞り込まれているか、境界データとして広いまま扱う理由が明確なら完了である。
