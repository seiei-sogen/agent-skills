== 前提

* 5100 番の puma が、この worktree（`feat/issue45412-backend-relink-closed-google-maps`）から動いていること。DB は `auto_reserve_development`。
* admin は `http://admin.lvh.me:5100/`。ログインは `http://lvh.me:5100/login` で `hello1@test.autoreserve.com` / `password1234`（`db/seeds.rb`）。
* 入力欄の成功経路（手順 8）とバッチの本実行（手順 9）は、ローカルから Google マップへ実際に通信する。ProxyMesh は通さない。

[IMPORTANT]
.ログイン後に画面上部の通知（toastr）が出ないときは、`lvh.me` の session cookie を消す
====
ローカルでは、`lvh.me:5100/login` でログインすると `_auto_reserve_session` cookie が `lvh.me` ドメインに作られ、admin を開くと同じ名前の cookie が `admin.lvh.me` ドメインにも作られる。
ブラウザは両方を admin へ送り、Rails は先に送られた `lvh.me` の方を読む。書き込みは `admin.lvh.me` の方に行くため、「付け替えました」などの flash が失われ、代わりにログイン時の「ログインしました」が出ることがある。
この PR の変更ではなく、ローカルの session 設定による（`config/initializers/session_store.rb` の `domain: :all`）。

対処: ログイン後に、DevTools の Application > Cookies で `http://admin.lvh.me:5100` を開き、Domain が `lvh.me` の `_auto_reserve_session` だけを削除する（`admin.lvh.me` の方は残す）。
通知が出なくても、画面の内容（一覧から消える、詳細の「最後の結果」が変わる）は正しく変わる。
====

=== 手順 9. バッチを流す（K7）

まず dry_run。worktree のルートで実行する。

[source,shell]
----

----

期待: `start dry_run=true target=1 limit=50 total=N` が出る。target の1件は予定を過ぎている K7。total は未解決の組の数（手順 5・7・8 のあとなら 4）。何も処理せず、Google にも通信しない。

次に、1件だけ本実行する。

[source,shell]
----
RAILS_LOG_TO_STDOUT=1 DISABLE_SPRING=1 bin/rails runner 'RecheckClosedGoogleMapLinksBatch.run(limit: 1)'
----

期待: 約60秒後に `processed web_system_id=... restaurant_id=... status=failed failure_reason=closed_place_fetch_failed` と `finished target=1 failed=1` が出る（閉業 place が架空なので Google から取れない）。
K7 の詳細を開き直すと、「最後の再チェック日時」が今、「次の再チェック予定」が今から14日後になっている。失敗も回数に数えるので、1回目の7日から2回目の14日に延びた。
