# Git ブランチ名を提案する

入力から issue 番号、対象領域、変更種別、主目的を特定し、コピーして使える Git ブランチ名を1件提案する。
ブランチの作成、切り替え、名前変更は、ユーザーが明示的に求めた場合だけ行う。

## 入力を確認する

変更内容、issue、仕様、作業メモなどの文章、またはローカルファイルのパスを受け取る。

読み取り可能なファイルのパスなら、パス、ファイル名、内容から判断する。
パスが存在しない、または読み取れない場合は、見えているパス要素だけを根拠にする。

次の必須情報を入力から特定する。

- issue 番号
- 対象領域が `frontend` と `backend` のどちらか
- 変更種別
- 変更の主目的

必須情報を推測できる根拠がなく、ブランチ名を確定できない場合は、汎用名で埋めずに不足情報を尋ねる質問を1つだけ返す。

## 命名形式

次の形式を必ず使う。

```text
feat/issue<issue-number>-<area>[-<change-kind>]-<slug>
```

各要素を次のように決める。

- `feat/` は固定の接頭辞とする。
- `<issue-number>` には入力の issue 番号を数字だけで入れる。たとえば `#195` は `issue195` とし、番号を改変・捏造しない。
- `<area>` は `frontend` または `backend` とする。
- `<change-kind>` は feature なら省略する。fix、refactor など、feature 以外なら変更種別を小文字で入れる。
- `<slug>` は変更の主目的を表す簡潔な英語にする。

省略可能な `<change-kind>` を省いたときも、ハイフンを重ねない。

### 対象領域を選ぶ

- UI、画面、ブラウザ、クライアント側の状態や操作が主対象なら `frontend` とする。
- API、データベース、migration、サーバー、worker が主対象なら `backend` とする。
- 両方を含む場合は変更の主目的がある側を選ぶ。主目的を判定できない場合は確認する。

### 変更種別を選ぶ

入力に `feat:`、`fix:`、`refactor:` などの明示があれば、その種別を優先する。
明示がなければ変更の主目的から判断する。

| 変更種別 | ブランチ名での表記 |
| --- | --- |
| feature | 省略 |
| 不具合修正 | `fix` |
| 外部の振る舞いを変えない実装整理 | `refactor` |
| 文書だけの変更 | `docs` |
| テストだけの変更 | `test` |
| 性能改善 | `perf` |
| CI の変更 | `ci` |
| ビルド処理や依存関係の変更 | `build` |
| その他の保守作業 | `chore` |

入力が曖昧という理由だけで `chore` を選ばない。

### Slug を作る

- 英語の小文字とハイフンを使う。
- 日本語はローマ字へ逐語変換せず、意味を保った短い英語にする。
- `detect-skipped-migrations` のように、変更を表す動詞と対象を優先する。
- 2〜6語、ブランチ名全体で60文字以内を目安にする。
- `change`、`update-stuff`、`misc` など、内容を特定できない語を避ける。
- issue 番号、対象領域、変更種別を slug 内で繰り返さない。
- OAuth、CLI、TSDoc などの技術語は、識別できる小文字表記にする。
- 入力にない対象範囲や目的を補わない。

複数の変更が含まれる場合は主目的を選ぶ。
独立した変更に分けるべき場合は、その旨を短く伝える。

## Git の制約を確認する

候補に次が含まれないことを確認する。

- 空白、制御文字、`~`、`^`、`:`、`?`、`*`、`[`、`\`
- `..`、`@{`、連続する `/`
- 先頭または末尾の `/` や `.`
- 末尾の `.lock`

候補を `-` で始めない。
Git を利用できる場合は、候補を引数にして検証する。

```bash
git check-ref-format --branch 'feat/issue195-backend-detect-skipped-migrations'
```

## 出力する

通常は第一候補を1件だけ、インラインコードで出力する。

```markdown
`feat/issue195-backend-detect-skipped-migrations`
```

変更種別や表現に意味のある選択肢がある場合だけ、第一候補に加えて代替候補を最大2件示し、違いを一言で説明する。
ブランチ作成コマンドや長い分析過程は、求められない限り出力しない。

## 例

| 入力 | 第一候補 |
| --- | --- |
| `#195 feat: migration の無言スキップを検知して db:migrate を停止する` | `feat/issue195-backend-detect-skipped-migrations` |
| `#208 fix: ログイン後に元の画面へ戻れない不具合を修正する` | `feat/issue208-frontend-fix-login-redirect` |
| `#310 refactor: API の認証処理を整理する` | `feat/issue310-backend-refactor-simplify-auth-flow` |
