# Commit Message Generator

差分全体の主目的を表すコミットメッセージを 1 つ生成する。

## 実行モデル

- Claude Code では、すでに Sonnet で動作している場合はそのまま実行する。それ以外の場合は、Sonnet を明示したサブエージェントへユーザーの依頼とこのスキルの手順を渡し、完了まで待つ。
- Sonnet またはサブエージェントを利用できない場合は、現在の agent が実行する。
- 委譲先はモデル選択を繰り返さず、コミットメッセージの生成だけを行う。

## 差分を確認する

- ユーザーから差分を渡された場合は、その差分を対象にする。
- Git リポジトリで差分が指定されていない場合は、現在のブランチ名と `git status --short` を確認する。stage 済みの変更があれば `git diff --cached`、なければ `git diff` と未追跡ファイルの内容を確認する。
- リポジトリ固有の言語や文体の規約がある場合は、その規約を表現へ反映する。
- 差分がない場合や、内容を確認できず主目的を判断できない場合は、推測でメッセージを作らず、その旨を簡潔に伝える。

## issue ID を付ける

現在のブランチ名に issue ID と分かる形で単一の ID が含まれる場合は、その ID を使う。
たとえば `feature/123-add-skill`、`issue-123`、`fix/#123` からは `123` を取得する。

日付やバージョン番号など、issue ID と断定できない数字は使わない。
候補がない場合や複数あって一意に決められない場合は、issue ID を付けない。

## プレフィックスを決める

差分全体の主目的から、次のプレフィックスを 1 つ選ぶ。

- `chore`: タスクファイルなど、プロダクションに影響しない修正
- `docs`: ドキュメントの更新
- `feat`: ユーザー向け機能の追加や変更
- `fix`: ユーザー向け不具合の修正
- `refactor`: リファクタリングを目的とした修正
- `style`: フォーマットなど、スタイルに関する修正
- `test`: テストコードの追加や修正

プロダクションコードとテストやドキュメントを同時に変更した場合は、プロダクションコードの主目的に合うプレフィックスを選ぶ。

## メッセージを作る

- ファイル名や作業内容の羅列ではなく、差分によって利用者やコードに起きる主な変更を書く。
- issue ID がある場合、1 行目を `<prefix>: #<issue-id> <件名>` とする。
- issue ID がない場合、1 行目を `<prefix>: <件名>` とする。
- プレフィックスの直後に半角コロンと半角スペースを置く。`#` は 1 つにし、issue ID と件名の間に半角スペースを 1 つ置く。
- 件名は日本語の短い 1 行にする。
- 1 行目の後に空行を置き、件名の内容を説明する本文を 1〜4 行で書く。
- 本文には変更の目的と重要な補足を書く。同じ件名の言い換えだけにしない。

出力形式は次のとおり。

```text
feat: #334 タイトル的なコミットメッセージ

タイトルの説明を 1〜4 行で書く。
```

コミットメッセージだけを 1 つ提示する。候補の列挙、理由の説明、commit や push は行わない。
