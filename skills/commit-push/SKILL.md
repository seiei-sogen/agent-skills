# Commit Push

現在の Git リポジトリにある未コミット変更を 1 つのコミットにまとめ、現在のブランチを push する。
現在のブランチ名から issue ID を取得できる場合は、コミット件名を `#<issue-id> <変更要約>` の形式にする。
issue ID を取得できない場合は、`<変更要約>` だけをコミット件名にする。

## 実行モデル

commit と push の実作業は、1 つの agent だけが担当する。

- Claude Code では、Sonnet を明示したサブエージェントへ、このスキルの全手順を委譲して完了まで待つ。すでに Sonnet で動作している場合は、そのまま実行する。
- Codex では、モデルを指定してサブエージェントを起動できる場合、現在より一段軽量なモデルへ、このスキルの全手順を委譲して完了まで待つ。
- 指定したモデルまたはサブエージェントを利用できない場合は、現在の agent が全手順を実行する。
- 委譲後、親 agent は同じ commit または push を重ねて実行せず、委譲先の結果を検証してユーザーへ報告する。

## 1. コミット前に対象を確定する

変更を加える前に、次を確認する。

1. `git rev-parse --show-toplevel` で Git リポジトリ内にいることを確認する。
2. 現在のブランチ、upstream、remote、未コミット変更を確認する。detached HEAD の場合は、コミット先ブランチをユーザーに確認する。
3. `git status --short`、`git diff`、`git diff --cached` を読み、未追跡ファイルの内容も確認する。未解決のコンフリクトがある場合は、対象ファイルを報告して終了する。
4. 変更がない場合は「コミットする差分がありません」と報告し、このスキルによる push は行わない。
5. 秘密鍵、認証情報、`.env` の実値など、公開すべきでない情報が含まれる可能性が高い場合は、該当箇所を値を伏せて報告し、コミット前にユーザーへ確認する。

## 2. issue ID と push 先を決める

現在のブランチ名に、issue ID と分かる形で含まれる単一の ID があるか確認する。
たとえば `feature/123-add-skill`、`issue-123`、`fix/#123` の `123` を issue ID として扱う。
日付やバージョン番号など、issue ID と断定できない数字は使わない。

issue ID を一意に取得できた場合だけ、コミット件名へ `#<issue-id>` を付ける。
明確な issue ID がない場合や複数候補がある場合は、issue ID なしのコミット件名を使う。

push 先はコミット前に確定する。

- upstream が設定済みなら、その upstream へ通常の `git push` を行う。
- upstream がなく `origin` がある場合は、現在のブランチを `origin` へ push し、upstream を設定する。
- push 先が存在しない、または複数候補から一意に決められない場合は、コミット前にユーザーへ確認する。
- push 先に含まれていない既存のローカルコミットがある場合は、その一覧を示す。今回の push でそれらも送信されることをユーザーへ確認してから進める。

## 3. コミット件名を作る

差分全体の主目的を日本語の短い 1 文で表す。
ファイル名の列挙ではなく、利用者やコードに起きる変更を書く。

ブランチ名から issue ID を取得できた場合は、次の形式にする。

```text
#<issue-id> <変更要約>
```

例:

```text
#123 引き継ぎメモを生成するスキルを追加
```

ブランチ名から issue ID を取得できない場合は、次の形式にする。

```text
<変更要約>
```

例:

```text
引き継ぎメモを生成するスキルを追加
```

issue ID を付ける場合、`#` は 1 つ、issue ID と変更要約の間は半角スペース 1 つとする。
どちらの形式でも件名全体は 1 行とする。

## 4. コミットして push する

1. `git add -A` で、削除と未追跡ファイルを含む現在の変更をすべて stage する。
2. `git diff --cached` と `git status --short` を再確認し、コミット対象が手順 1 で確認した範囲と一致することを確かめる。
3. `git commit -m '<件名>'` で 1 回コミットする。commit hook が失敗した場合は回避せず、エラーと現在の状態を報告して終了する。
4. 作成されたコミットの件名と hash を確認する。
5. upstream がある場合は `git push` を 1 回実行する。upstream を新設する場合は `git push --set-upstream origin <現在のブランチ>` を 1 回実行する。
6. push が失敗した場合は、force push、rebase、pull、追加コミットへ進まず、ローカルに作成済みのコミット hash とエラーを報告する。

## 5. 完了を報告する

push 後に、ローカルの `HEAD` と upstream の追跡参照が同じ commit を指すことを確認する。
次を簡潔に報告する。

- ブランチ名から取得した issue ID。取得していない場合は `なし`
- 実際のコミット件名
- コミット hash
- push した remote とブランチ
- 作業ツリーに残っている変更の有無
- 実行した検証と、実行していない検証

コミットが作成され、同じ commit が確定した push 先に存在すると確認できた時点で完了とする。
