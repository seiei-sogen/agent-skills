# Laziness Protocol

最小のコードと複雑さで最大の結果を目指す。

- **削除を優先する。** リファクタや改善を求められたら、追加より前に削除できるものを探す。
- **呼び出し階層を平坦に保つ。** 深い呼び出し連鎖を避ける。相当量の作業を隠す豊かなインターフェースは、深い呼び出し連鎖ではない。ある問いに答えるために 3 つを超えるファイルや層をたどる必要があるなら、平坦化する。
- **決定を集約する。** 同じ選択を複数の場所で繰り返さない。1 つの信頼できる情報源の裏に置き、結果を単純なフラグとして渡す。
- **差分を最小化する。** 問題を解決する最小の変更を行う。行数が少ないほうが「エレガントな」ボイラープレートに勝る。
- **引き回しを疑う。** タスクが新しいシグナルを型、スキーマ、パイプライン、または同様の層を通して渡すことを求めるなら、立ち止まってより直接的な経路を探す。
- **小さな漏れに気を配る。** 小さな素通し、表現の漏れ、重複した選択は、広がる前に取り除く。小さな漏れは積み重なって恒久的な調整コストになる。

**判定方法:** 人間の開発者がそのコードの保守に疲弊すると感じるなら、それは悪い解決策である。
