# PR の面倒を見る

Cursor 組み込みの `/babysit` に相当する Claude Code 向けスキル。実装は `gh` CLI のループに、ペース配分のための Claude Code の `loop` スキルを組み合わせたものである。

**プラットフォームに関する注記。** Codex やその他の非 Claude ランタイムでは、以下に挙げる Claude のツール名と Claude 組み込みスキル（`loop`、`AskUserQuestion`）は Claude の既定値である。[`codex-tools.md`](../poteto-mode/references/codex-tools.md) を通じて解決すること。

poteto-mode の中では、**Babysit** プレイブック（[`../poteto-mode/playbooks/babysit.md`](../poteto-mode/playbooks/babysit.md)）がこのスキルに優先する。プレイブックはモード宣言、マージフロンティア、スタックの安全性、`watch-pr` ウォッチャーを担う。このスキルは、poteto-mode の実行外で単一の PR を扱うための、単独の `/babysit` エントリポイントとして残る。

## 使うとき

- 開いている PR があり、ユーザーがそれをグリーンに保つことを明示的に望んでいて、かつ自分がまだ poteto-mode の実行中ではない場合（その場合はプレイブックが担う）。
- ユーザーが `/babysit` を直接呼び出した場合。
- PR を開いたサブエージェントは決して面倒を見ない。親へ戻り、親に判断させる。

## 手順

1. **PR の状態を取得する。**

   ```bash
   gh pr view <number> --json number,title,state,mergeable,reviewDecision,statusCheckRollup,mergeStateStatus,comments,reviews
   ```

2. **優先順位に沿ってトリアージする。**
   - マージ競合（`mergeStateStatus == DIRTY`）: `main` を rebase またはマージし、解消する。force-push は、そのブランチが自分のもので共有されていない場合に限る。
   - 失敗しているチェック（`statusCheckRollup` のエントリが `conclusion: FAILURE`）: `gh run view <run-id> --log-failed` でログを取得する。失敗の根本原因を特定し、元になっているコードまたはテストを直し、コミットして push する。
   - 人間のレビュアーからのレビューコメント（`gh pr view --json comments,reviews`）: 本当に同意できるフィードバックにだけ対応する。コメントに機械的な答えが 1 つしかない場合（リネーム、ガード節、フォーマットの細かい指摘）は、編集を行い、コミットメッセージにコメントを引用する。判断が必要な場合や、何を求められているか分からない場合は、推測しない。そのまま残し、自分ならこうしていたという内容を返答する。
   - レビューボットのコメント（Bugbot や同様の自動化）: [`../poteto-mode/references/bugbot-triage.md`](../poteto-mode/references/bugbot-triage.md) に従い、修正、却下、行動前に確認のいずれかに分類する。セキュリティ、データ、高い深刻度の指摘を含む、ルーブリックの「既定で確認する」カテゴリに従う。

3. **ループする。** Claude Code の `loop` スキルを使って再確認のペースを配分する。見守っている対象に応じて間隔を選ぶ。
   - 実行中の CI: `gh pr checks --watch` でポーリングする（チェック完了までブロックするので、別途ループ間隔は不要）。
   - レビュアー待ち: 20〜30 分のハートビート。
   - 待機中だが新しいコメントを拾いたい: 1 時間ごと。

4. **止めるとき。**
   - ビルドがグリーンで、すべてのコメントが解決済みで、ブランチがきれいにマージできる。準備完了と宣言する。
   - 修正、push、再確認のラウンドを 3 回実行してもまだ完全にグリーンにならない。停止し、まだ壊れているものを要約し、制御を返す。
   - 次の修正が設計上の選択を強いる。一時停止し、`AskUserQuestion` でユーザーに委ねる。

5. **報告する。** 適用した修正、対応したコメント、保留したコメント（理由付き）、現在の PR 状態を要約する。各コミットを SHA で引用する。

## 厳守ルール

- 他者が pull した可能性のあるブランチの履歴を書き換えてはならない。rebase や force-push が必要に見える場合は、まずユーザーの了承を得る。
- テストを通すためだけにテストの期待値をいじってはならない。アサーションを変えるのは、振る舞いが本当に変わり、アサーションが古い振る舞いに固定されていた場合に限る。
- フックをスキップしてはならない（`--no-verify`）。
- 失敗しているチェックを必須でないとマークして回避してはならない。
- `gh pr ready` は、すべてのチェックがグリーンで、未解決のレビューコメントが残っていないときに限る。

## 来歴

これは Cursor の `/babysit` に相当する Claude Code 向けスキルであり、移植ではない。Cursor の実装はクローズドソースである。このスキルは独立して執筆され、独自の文章と構成を持つ。ワークフローは Cursor の公開されている `/babysit` の振る舞いを参考にしている。他の PR ツールとの唯一の重複は実行する `gh` CLI コマンドであり、これはコピーされたテキストではなく機能的な呼び出しである。
