# CI を直す

## トリガー

ブランチまたは PR の CI が失敗しており、チェックをグリーンにするための速い反復的な経路が必要なとき。

## ワークフロー

1. アクティブな PR を特定し、`gh pr checks --json name,bucket,state,workflow,link` を調べる。
2. 失敗したジョブを調べ、最初の対処可能なエラーを抽出する。利用できるなら GitHub Actions のログを使う。そうでなければチェックのリンクを使って、失敗しているコマンドやサービスを特定する。
3. 最小で安全な修正を適用する。
4. push し、PR のチェック一式を再確認し、グリーンになるまで繰り返す。

## ガードレール

- 対処可能な失敗は一度に 1 つずつ直す。
- 広範なリファクタより先に、最小で低リスクな変更を優先する。
- PR の CI 全体の状態については、`gh pr checks` を唯一の情報源として扱う。

## 出力

- 主要な失敗ジョブと根本のエラー
- 反復の順に並べた適用済みの修正
- 現在の CI の状態と次のアクション
