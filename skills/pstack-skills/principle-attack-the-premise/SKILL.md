# Attack the Premise

1 つの前提を共有する 2 つ以上の修正が同じゲートで失敗したときは、修正ではなく前提を疑う。

**理由:** 共有された前提の下での失敗は、1 回ごとにその前提についての証拠になる。

**パターン:**
- **前提を書き出す。** 前提とは、失敗したすべての修正が仮定していた 1 文のことである。
- **不均衡の問題では、次の修正の前に実態調査を行う。** アクターごとに不均衡を数え、どのアクターがそれを抱えているかを検証する。実態調査は [Build the Lever](../principle-build-the-lever/SKILL.md) に従って再実行可能なスクリプトとして書く。
- **実態調査が偏りを示したら、それを調査する。** 毎回の実行で同じ少数のアクターが不均衡の大半を抱えているなら、何かがそのアクターにその役割を割り当てている。役割を割り当てているものを見つける。その割り当てが、[Fix Root Causes](../principle-fix-root-causes/SKILL.md) に従う次の「なぜ」である。
- **役割の割り当てが不均衡を引き起こしているときは、補償するのではなく、その非対称性を取り除く。** これは [Laziness Protocol](../principle-laziness-protocol/SKILL.md) に従う。役割をアクター間で交代させる、割り当てをランダム化する、または役割を移動して、どのアクターも毎回の実行でその役割を抱えないようにする。返却経路、共有プール、バッチ化した引き渡し、定期的なリバランスは、割り当てをそのまま残し、毎回の実行に作業を追加する。

**停止:**
- 前提を書き出して検証するまで、次の修正を始めない。不均衡の仮説では、実態調査を含める。
- 実態調査がアクター間で均等なら、それは非対称性の仮説に反する証拠であり、共有された前提が正しいことの証明ではない。前提を疑い続け、実態調査を証拠として保持する。

この原則は [Redesign from First Principles](../principle-redesign-from-first-principles/SKILL.md) とは異なる。あちらは新しい要件を中心に設計を作り直す。この原則は、現在の設計が仮定している事実を疑う。
