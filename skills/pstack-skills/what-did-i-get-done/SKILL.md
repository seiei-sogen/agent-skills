# What did I get done

## トリガー

特定の期間（例: 昨日、直近 3 日、先週）に完了した作業について、短くて情報量の高い要約が必要なとき。

## ワークフロー

1. 要求された期間を具体的な日付に解決する。
2. その範囲内で、現在の git ユーザーのメールアドレスが作成者であるコミットを読む。
3. マージコミットと未コミットの変更を除外する。
4. 出荷された最も重要な変更を、簡潔な状況報告に統合する。
5. 最終的な要約に、実際に使った日付範囲を含める。

## ガードレール

- 極めて簡潔で、情報密度を高くする。
- 実質的な振る舞いやアーキテクチャの変更を優先する。
- 見た目だけの変更（フォーマット、インポート、小さなリネーム）は省く。
- 意図や動機を推測しない。変更を機能面から記述する。

## 出力

- 状況報告に適した短い要約 1 つ
- 実際の日付範囲
- 主要な変更に限った、任意の 2〜5 個の箇条書き
