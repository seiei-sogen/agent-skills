# Outcome-Oriented Execution

滑らかな中間状態を保つことではなく、意図した検証可能な最終状態に向けて最適化する。

**理由:** すべての中間ステップを完全に安定させ続けると、一時的な互換コードが生まれ、それが長寿命の負債になることが多い。目標アーキテクチャへ収束させ、明示的な検証境界で正しさを証明する。

**中心となるルール:**
- 過渡期の安定性より最終状態の完全性を優先する
- 中間段階での破損は、計画され、範囲が限定され、可逆であれば許容できる
- 完了を宣言する前に必ず最終検証を実行する

**ガードレール:**
- これは明示的なフェーズ境界を持つ計画済みの書き直しや移行に使う
- 一時的な破損を許容する場所を宣言する
- 移行中は、実際に触れている領域に対するシグナルの強いチェックを維持する
- 計画の完了時に、静的検証と実行時検証の両方を完全に要求する
