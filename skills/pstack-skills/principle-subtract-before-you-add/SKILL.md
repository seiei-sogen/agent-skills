# Subtract Before You Add

システムを進化させるときは、まず複雑さを取り除き、それから構築する。

**理由:** 複雑なシステムに追加すると、複雑さは複利で増える。まず取り除けば、コードは少なくなり、本質的な構造が見え、たいていは次の設計が明白になる。既定を引き算にする。

単純化を継続的な投資にする。同じかより小さいサーフェスの裏で、設計を見つけたときより少し単純で、より有能な状態にして残す。

**パターン:**
- 構築より前に除去を並べる
- 磨く前に削る（品質に投資する前に最小限に到達する）
- 投機的なエッジケースではなく、観測された使い方に合わせて設計する
- 仕様が要求する以上の投機的なバリデーター、パーサー、ガードを作らない
- プロンプトを単純化する（冗長な指示、過剰なテンプレートを取り除く）
- 参照に新しい内容がないときは、スタブを残すのではなく削除する
