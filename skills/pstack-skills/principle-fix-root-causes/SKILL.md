# Fix Root Causes

デバッグ時は、症状を修正しない。すべての問題を根本原因までたどり、そこで修正する。

**理由:** 症状の修正は蓄積する。回避策のひとつひとつがシステムを推論しにくくし、本当のバグは残る。根本原因の修正は最初は遅いが、デバッグの総時間を減らす。

**パターン:**
- まず再現する
- 根本原因に到達するまで「なぜ」を問う
- ガードを追加しない（クラッシュを黙らせるために nil チェックを追加するのは症状の修正である）
- 回避策を正当化するのに段落ほどの長さのコメントが必要なら、コードが間違っている（コメントではなくコードを直す）
- 事例だけでなくパターンを確認する（同じパターンを grep し、すべての事例を修正する）
- 行き詰まったら計装する。推測しない（ログを追加し、実際のエラーを読む）

**再起動のバグ: コードより先に状態を疑う**

何かが「再起動後に失敗する」ときは、まず古くなった永続状態を疑う。設定ファイル、キャッシュ、ロックファイル、シリアライズされた状態。状態ファイルを消すと動作が戻るなら、修正として状態のバリデーションを優先する。
