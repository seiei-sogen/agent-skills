# 認識論

証拠が歴史的で、断片的で、ときに矛盾するときに確信度をどう推論するか。そして、それを偽りの確実さへ平坦化せずにどう伝えるか。

コードは自身の動機を持ち歩かない。コードが何をするかは読める。*なぜ存在するか*は読めない。それはコミット、PR、チケット、ドキュメント、会話の中にあり、それらはすべて不完全で、偏りがあり、ときに完全に欠けている。そうでないふりをすると、自信ありげに聞こえる推測が生まれ、ユーザーを誤らせる。

## 確信度の階層

最終出力のすべての主張は、次の階層のいずれかに置かれなければならない。階層によって、主張がどの出力セクションに入り、どう言い表されるかが決まる。

### 1. Direct

問いに答える、明示的で文字として残った引用。「コードが X をするから作者は X を望んだに違いない」ではない。作者が実際に*書いた*、理由を述べる何か。

例:
- 「1000 件超のアイテムを持つユーザーがページ送りできないバグを修正する」と書かれた PR の説明
- 「顧客 Acme がセキュリティレビューで要求したので追加する」と書かれたチケット
- 「// clamp to 100 because the upstream API rejects larger values」と書かれたコードコメント
- 「再起動をまたいだ永続化が必要なので、選択肢 B ではなく選択肢 A を選んだ」と書かれた設計ドキュメント
- 「旧方式はテストで不安定だったのでこの方式に切り替える」という作者のチャットメッセージ

言い回し: 確信をもって、現在形で。「これは X のために存在する。」ソースを引用する。

### 2. Supported

複数の間接的な証拠が収束する。単一のソースが明示的に述べているわけではないが、ソース横断のパターンからそれが確からしい。

例:
- PR タイトルが「パフォーマンス改善」、チケットのラベルが「perf」、周囲のコミットがすべて同じホットパスに触れている
- 変更と一緒に複数のテストが追加され、すべて非常に大きな入力のエッジケースを検証している
- 同じ週の作者の他の PR が、説明ですべて同じインシデントに言及している

言い回し: 確信をもって、ただし導出したものだと明確に。「証拠は X を強く指し示す: [具体的な証拠]。」複数のソースを引用する。

### 3. Inferred

コンテキストの合理的な読み解きだが、明示的に支持するものはない。読者は、これが記録上の事実ではなく*自分の解釈*だと理解すべきである。

例:
- PR には理由が書かれていないが、エラーが本番で発生しており（インシデントチャンネルのタイミングから）、修正が急がれていた（同日にマージ）ことから、おそらくホットフィックスだった。
- 関数名はリトライロジックを示唆する。リトライ回数は 3。これはコードベースの他の場所で見られるチームの一般的な慣習「3 回リトライ」と一致する。

言い回し: 保険をかける。「〜のようだ」「おそらく」「〜を示唆する」「〜と整合する」「一つの読み方は」。推論の連鎖を明示する。「A と B を踏まえると、D のため C が確からしい。」

### 4. Speculative

もっともらしい仮説だが、証拠は薄く、他の説明も同程度に当てはまる。これを提示することには価値があるが、推測であると明確に印を付ける。

例:
- 「これはすでに修正されたブラウザのバグへの回避策かもしれないが、当時の証拠は見つからなかった。」
- 「このしきい値は SLA の約束に合わせて選ばれた可能性があるが、それを参照する SLA ドキュメントはない。」

言い回し: 明示的に推測として。「一つの可能性は X だが、直接の証拠はない。」通常は「Competing Hypotheses」セクションに、他の可能性と並べて置く。

### 5. Unknown

調べたが分からなかった。有効かつ重要な結果である。記録する。

言い回し:「X、Y、Z を検索したが、理由の証拠は見つからなかった。」*何を*検索したかを具体的に述べる。「分からなかった」は、「チケットトラッカーをキーワード A と B で検索し、2023 年以降にこのファイルに触れた 6 件の PR を確認し、しきい値に一致する文字列リテラルをリポジトリで grep した。いずれも根拠説明を浮かび上がらせなかった」より役に立たない。

## 言い回しガイド

### 確信を帯びる語。慎重に使う

これらは **Direct** または **Supported** の確信度を含意する。推論には使わない。

- 「〜のため（because）」。証拠のある因果の主張を含意する
- 「理由は〜である（the reason is）」。同上
- 「〜するよう設計された（was designed to）」。作者の意図を主張する
- 「修正する（fixes）」「対処する（addresses）」「解決する（solves）」。変更が目的を達成したと主張する
- 「チームは〜と決定した（the team decided）」。集団の決定があったと主張する

これらを使うなら、すぐ隣に引用があるべきである。

### 保険をかける語。推論に使う

- 「〜のようだ（appears to）」
- 「〜と見える（seems to）」
- 「おそらく（likely）」
- 「〜を示唆する（suggests）」
- 「〜と整合する（is consistent with）」
- 「一つの読み方は（one reading is）」
- 「もっともらしくは（plausibly）」
- 「〜だったかもしれない（may have been）」
- 「証拠は〜を指し示す（the evidence points toward）」

これらは、報告ではなく解釈をしていることを示す。「What We Can Reasonably Infer」セクションでは惜しまず使う。

### 避ける語

- 「明らかに（obviously）」。明らかなら、ユーザーは尋ねていない
- 「はっきりと（clearly）」。ほぼ常に、はっきりしていない主張の前に置かれる
- 「もちろん（of course）」。同上
- 「単に（just）」（「単にパフォーマンスのための X だ」のように）。突き放した言い方で、通常は不確かさを隠す
- 「私は思う（I think）」「私は信じる（I believe）」。証拠を統合しているのであり、個人的な意見を述べているのではない。代わりに「証拠は〜を示唆する」を使う。

### 合理化を避ける

今日「筋が通る」コードは、もはや当てはまらない理由や、書かれた当時から間違っていた理由で書かれたのかもしれない。乱雑な履歴にきれいな根拠説明を後付けしない。

次の衝動に抵抗する:
- 作者が「正しい」ことをしたと仮定し、さかのぼって正当化する
- コードベース全体で一貫したパターンが意図的だったと仮定する。コピペかもしれない
- 証拠の不在を不在の証拠にする（「誰もセキュリティ上の懸念を挙げなかったので、懸念ではなかったに違いない」）

## 迎合の罠

ユーザーは `why` の問いに仮説を埋め込んで尋ねることが多い。「なぜこうしているのか、パフォーマンスのためだと思うが?」それを単純に肯定しない。複数の候補の一つとして扱い、証拠を独立に確認する。証拠がそれを支持するなら、引用付きでそう言う。支持しないなら、そう言い、証拠が*実際に*支持するものを提示する。

ユーザーの推測は調査のきっかけであり、正しいと裏付けるべき結論ではない。

## 証拠が矛盾するとき

2 つのソースが食い違う場合（PR の説明はある事を言い、チケットは別の事を言う）、両方を浮かび上がらせる。きれいな筋書きに合う方を選ばない。典型的なパターン:

- **チケットは**「顧客 X のコンプライアンス要件のためにこれが必要だ」と言う
- **PR は**「この領域の技術的負債を片付ける」と言う

両方が真かもしれない（チケットが作業の動機で、PR は作者によるその枠付け）し、一方が間違っているかもしれない。両方を引用付きで提示し、ユーザーに判断を委ねる。

## 証拠が欠けているとき

正直な「分からない」は、このスキルが生み出せる最も価値ある出力の一つである。これによりユーザーは次を知る:

- 答えは分かりやすい場所にはない
- 知るには人間（元の作者、プロダクトオーナー、チームリード）に尋ねる必要がある
- あるいは、この問いはこれ以上追う価値がないと判断できる

ギャップに印を付けず、自信ありげな推測で埋めることは、ユーザーに実害を与える。ユーザーはその推測に基づいて行動する。

ギャップに当たったら、具体的に名指しする:
- どの問いに答えようとしていたか
- どのソースを検索したか
- それぞれで何を検索したか
- 何を見つけたか（何もない、あるいは間接的に関連する資料のみ）

## 確定前の校正チェック

出力を届ける前に、シンセサイザーは「What We Found」と「What We Can Reasonably Infer」のすべての主張を見直し、次を問うべきである:

1. この主張に引用はあるか。なければ、引用を追加するか、「Inferred」/「Hypotheses」へ移す。
2. 言い回しは階層に合わせて校正されているか。（Direct の主張は「〜のため」を使える。Inferred の主張は使えない。）
3. コードそれ自体を、その意図の証拠として扱っていないか。そうなら、それは証拠ではない。削除するか再分類する。
4. 出力に「What We Don't Know」セクションはあるか。ギャップが一つも挙がっていなければ、それは疑わしい。証拠が異例なほど完全だったか、何かが隠されている。
