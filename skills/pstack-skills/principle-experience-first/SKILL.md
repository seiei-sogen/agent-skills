# Experience First

実装の都合とユーザーの喜びが衝突したら、喜びを選ぶ。

- すべての機能、コントロール、オプションは正当化されなければならない
- 少なく出荷し、より良く出荷する（3 つの機能を磨いた体験は、10 個の機能を持つ粗い体験に勝る）
- 確定する前にプロトタイプを作る（設計上の決定は、本番コードより使い捨ての HTML のほうが安い）
- 細部を正しくする（トランジション、整列、余白、フィードバック、エラー状態）
- コアループを引き締める（すべての機能は中心的なワークフローに役立つか、さもなければ邪魔にならないようにする）

ユーザーとは、その成果を利用する人のことである。UI ならエンドユーザーである。ライブラリや内部 API なら、それをインポートする同僚である。次にそのコードを保守するエンジニアもユーザーである。その体験を同じように重み付けし、影響をその視点から説明する。

基盤は体験に役立つべきである。Foundational Thinking は作業の *順序* を支配する。この原則は *目標* を支配する。
