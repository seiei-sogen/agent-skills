# Swarm

N 個の並列ワーカーをファンアウトする。ワーカーは別々の断面を担当してもよいし、同じブリーフでレースしてもよいし、両者を混ぜてもよい。親は待機し、集約し、1 つのレポートを返す。

**ディスパッチ契約。** 各ワーカーのディスクリプタを [`provider-dispatch.md`](../poteto-mode/references/provider-dispatch.md) を通して解決する。ネイティブレーンと外部レーンを起動するのは親であり、ワーカーが自分自身をルーティングすることはない。Codex では、残りの Claude ツール名を [`codex-tools.md`](../poteto-mode/references/codex-tools.md) で解決する。

## 開始

何かを起動する前に、フェーズごとに 1 項目の TODO リストを開く。

1. 枠組みを決める
2. ファンアウト
3. 集約
4. レポート

## Phase A: 枠組みを決める

1. 完了条件と、swarm が返すべき成果物またはレポートを述べる。
2. 形を選ぶ。断面に分割する、同一のブリーフで N 個のワーカーをレースさせる、または両者を混ぜる。レースまたは混合の形では、起動する前に `first pass`、`rank all`、`best-of` のいずれかを宣言する。
3. N をユーザーから受け取るか、形から導く。N はワーカーの総数であり、同時に走る数ではない。
4. 現在のハーネスの pstack モデルシートに `swarm workers` があればそこからワーカーのディスクリプタを選ぶ。なければ `grok:grok-4.6@xhigh` を使う。モデルのレースでは、各アームのディスクリプタを前もって名指しする。
5. 書き込みを行うワーカーには、それぞれ専用の書き込み可能な出力先を与える。

## Phase B: ファンアウト

N 個すべてのワーカーを、プロバイダディスパッチ経由で 1 回のファンアウトフェーズで起動する。ネイティブレーンはバックグラウンドのサブエージェントを使い、外部レーンはタスク / セッションのハンドルを保持したままランチャーをバックグラウンド作業として呼び出す。長時間動くワーカーに Claude のフォアグラウンド Bash 経路を使ってはならない。書き込みを行うワーカーはすべて、割り当てられたワークツリーまたは出力ディレクトリの中で動く。分離はそのパスによって得られるもので、プロバイダによるものではない。

ワーカーがデフォルトでないブランチから始めなければならないときは、そのブランチをワーカー専用のワークツリーにチェックアウトし、ブリーフの中でワークツリーのパスを名指しする。

各ブリーフはそれ単体で成立させる。目標、スコープ、正確な断面またはレースのアーム、検証方法、報告内容を含める。レポートは `PASS`、`ISSUES`、`BLOCKED` のいずれかを証拠付きで使う。

ワーカーが脱落したら、N-1 で続行し、プロバイダ、モデル、レシートの失敗を記録する。別のプロバイダを黙って代わりに使ってはならない。

## Phase C: 集約

最終結果を読む。カバレッジでは、必要なすべての断面に結果がなければならない。レースでは、前もって宣言した選択ルールを適用する。first pass、rank all、best-of のいずれかを使う。ワーカーの生の出力をそのまま貼り付けない。

コンパクトな結果の表、証拠付きの 1 行の問題、明示的な隙間や脱落を保つ。

## Phase D: レポート

表、問題の 1 行要約、隙間や脱落、使った場合はレースのルールを含む 1 つの統合レポートをチャット内で返す。
