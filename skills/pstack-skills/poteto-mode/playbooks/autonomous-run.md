### Autonomous run

**終了条件の責任は自分にある。完了を定義し、止まらずにそこまで駆動する。**

1. 最初のイテレーションの前に、終了条件を検査可能な述語として述べる（テストがグリーン、再現が修正済み、N 件の PR がすべてマージ済み、ピクセル差分がゼロ）。
2. Claude Code の `loop` スキル（組み込み）を使ってウェイク機構を選ぶ。監視すべきイベント（CI、マージ、ref の前進）があるなら、そのイベントで自分を起こすウォッチャーサブエージェントを用意し、長い時間ベースのハートビートをフォールバックにする。イベントがないなら、結果を再確認する価値が出る時点に合わせた固定間隔のハートビートにする。
3. 各イテレーションは、証拠が正当化する最小の変更を行い、述語に対して検証し、前進したならコミットし、役に立たなかった変更は破棄する。「効くかもしれない」念のための二重対策は、残したまま乗せておくのではなく戻す。
   **sequence-verifiable-units** 原則スキルに従って作業を順序付け、最後にまとめて確認するのではなく、各ユニットを次に進む前に検証する。
4. 実行中の発見は自分のものだ。壊れたスキル、関連するバグ、不安定な検証器、レビューのノイズ、ツールの失敗、放置されたフォローアップ、修正可能なドリフトには、poteto-mode を通じて自分で対処する。本筋外の修正は独立した PR に入れる。可逆な作業を人間のために保留したり、`AskUserQuestion` を使ったりしない。表に出すのは、不可逆なアクション、実験では決着しない本物のプロダクトや好みの判断、本物の行き止まりだけにする。述語を主軸として保ち、各副次的な修正の後にはそこへ戻る。
5. **show-me-your-work** スキルを通じて各イテレーションでチェックポイントを取る。何を変えたか、述語が動いたかを 1 行にする。
6. 述語が満たされたら止める。停滞は停止ではないので、続行し、乗り越えるためにアプローチを転換する。空回りするより本物の行き止まりを表に出し、勝利を宣言するために述語を緩めることは決してしない。

**返答:** 終了条件、実行したイテレーション数、取り込まれたもの、破棄されたもの、述語の最終状態。
