### Worktree and simulator cleanup

**ディスクと安全ゲートの責任は自分にある。** マージ済みまたは放棄された git ワークツリーと古い iOS シミュレータを刈り込み、容量を取り戻す。削除は不可逆なので、すべてのステップで、使用中のものや未コミットの作業を抱えるものを削除しないようガードする。

1. スナップショットを取り、監査する。`df -h /` を記録し、次にインストール済みプラグイン配下で `skills/poteto-mode/scripts/worktree-audit.sh` を実行する（principle-build-the-lever）。これは手打ちではなく `git worktree list` からパスを読む。手打ちの `myrepo-worktrees/x` では `.worktrees/myrepo/x` にあるものを取り逃すからだ（principle-encode-lessons-in-structure）。各ワークツリーをサイズ、経過日数、マージ状態、未コミットの作業、PR の状態、それに触れた最新のチャットで分類し、バケットを提案する。トランスクリプトのスキャンは遅いので、バックグラウンドで実行する。
2. バケットは助言であり、許可ではない。ピン留めされたチャットとアクティブなチャットが本物の成果物である（principle-prove-it-works）。そのセットをユーザーまたは自分のセッション一覧から取得し、すべての候補を照合する。このてこはユーザーがピン留めしていたワークツリーを `safe` と印付けたことがあるので、ピン留めされたセットが優先する。
3. 削除する前に使用状況を検証する。すべての `verify-recent-chat` の行、または疑わしいものについては、サブエージェントをファンアウトしてトランスクリプトを読ませ、そのチャットがピン留めされているか進行中か、どのワークツリーに触れているかを報告させる（principle-guard-the-context-window、トランスクリプトは大量である）。ピン留めされたチャットはバックグラウンドのサブエージェント経由で arena や再現のツリーを兄弟ワークツリーに生成し、それらはその名前がセッション一覧に決して現れなくても使用中である。
4. 不可逆な損失の前で一時停止する。`wip:N` は N 件の追跡済み未コミット編集を意味する。まず差分を見せて決定を得る。クリーンなワークツリーの削除はそのブランチから復元できるが、未コミットの作業は消えるからだ。`scratch:N` は追跡されていない使い捨てで、落として安全だが、ファイル名は挙げる。Autonomy に従い、クリーンかつマージ済みかつ未使用のものは進める。`wip` と使用中のものは一時停止する。
5. 確認済みのセットを刈り込む。パスごとに `git worktree remove --force <path>`。無視された（ignored）ビルド成果物のためにディレクトリが残るなら `rm -rf` し、次に `git worktree prune`。ブランチの ref は残るので、コミットは失われない。`df -h /` で確認し、再度一覧する。
6. シミュレータとその他の回収先。シミュレータは通常、次に大きな回収先である。`xcrun simctl --set testing delete all`（XCTestDevices のクローン）、`xcrun simctl delete unavailable`、古いランタイムには `xcrun simctl runtime list` の後に `runtime delete <id>`。さらに必要なら、Xcode の `DerivedData` と `iOS DeviceSupport`、エディタのアプリケーションサポートのキャッシュ、`~/.claude/shell-snapshots/` と古い `~/.claude/projects/` のトランスクリプト（**recall** スキルと Session pickup が読む最近のものは残す）、パッケージキャッシュ（pnpm、uv、brew、yarn）。ユーザーが残すと言っていないキャッシュだけを消す。

これは、手違いを捕まえるコードレビューなしにユーザーの状態を削除する唯一のプレイブックなので、上のゲートがレビューである。

**返答:** 前後の `df -h /` と取り戻した容量、刈り込んだワークツリー、保留した各ワークツリーの 1 行の理由（どのチャットが使用中か、または未コミットの作業）。
