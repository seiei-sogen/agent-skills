### Session pickup

**再開点の責任は自分にある。以前の記録を読み、やり直さない。**

1. 以前の記録を見つける。Claude Code のプロジェクトごとのトランスクリプトディレクトリ `~/.claude/projects/<encoded-cwd>/*.jsonl` 配下のローカルトランスクリプト（`<encoded-cwd>` はワークスペースの cwd の `/` を `-` に置き換えたもの。`~/.claude/projects/` 配下の他のディレクトリをまたいで glob しない。それはワークスペースの境界を越え、無関係なプロジェクトの私的なチャットを読むことになる）、クラウドエージェントの URL、または push 済みのブランチ。まずメタデータの概要と最後のメッセージを読み、次に決定点を探して遡る。長いトランスクリプトはサブエージェントでパースし、絞り込んだタイムラインをメインスレッドに保つ（**principle-guard-the-context-window** スキル）。
2. 運用状態を再構築する。ブランチとワークツリー、すでに取り込まれたもの（`git log`、ベースに対する `git diff`）、開いている TODO、行われた決定。以前の記録は権威ある入力である。それを再導出しようとするバイアスに抗う。
3. 完了と未完了の差分を取る。出荷されたものと計画されていたものを比較し、再開点を名指し、以前の再現を再実行したり完了した作業をやり直したりしない。「ゼロから検証させてほしい」というパスは、権威あるはずの記録を信頼できないものとして扱っていることを意味する。
4. 残りの作業を一致するプレイブックへルーティングし、判定を選ぶ。実行を続ける、完成した推奨を出荷する、以前の結論を承認または覆す、あるいは失敗した実行をポストモーテムする。pickup プレイブックはここで終わる。ルーティング先のプレイブックが残りを担う。
5. 引き継いだ主張を、実際の成果物で元の目標に対して検証する（**principle-prove-it-works** スキル）。以前の合格という自己報告は証明ではない。

**返答:** 以前のエージェントがどこで止まったか、引き継いだものとやり直したもの（理想はやり直しゼロ）、再開点、結果。
