### Runtime forensics

**診断の責任は自分にある。生きているプロセスを計装し、ソースから理論を立てない。** 納品物は引用付きの診断であり、修正ではない。

1. ドライバースキル（CLI と TUI には `run`、UI には `verify`）を通じて、一致するサーフェスでライブの信号を取得する。空回りしているプロセスには CPU プロファイル、リークにはヒープスナップショット、視覚的な不具合には CDP トレース。推測ではなく、実際の成果物。
2. 成果物を決定的証拠まで絞り込む。ホットパス上の関数、リークしたオブジェクトから GC ルートまでのリテイナーチェーン、入力なしに発火しているループ。大きな成果物はサブエージェントでパースし（**guard-the-context-window** 原則スキル）、絞り込んだ指摘をメインスレッドに保つ。
3. 信じる前にメカニズムを証明する。実行中のプロセスに CDP eval で計装を注入するか、リロードせずにライブのコードをホットフィックスして、仮説を安価に確認する。
4. 指摘をソースに対応付ける。ファイル、シンボル、割り当てまたはスケジュールしている行。
5. スループットチェックポイントは 1 行にとどめる: `throughput checkpoint: n/a, read-only forensics`。

**返答:** 取得した信号、絞り込んだ指摘、メカニズムをどう証明したか、ソースの位置、成果物のパス。求められない限り修正はしない。原因が分かったら Bug fix または Perf に引き渡す。
