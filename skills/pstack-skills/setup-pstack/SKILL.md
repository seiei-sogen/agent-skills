# Setup pstack

現在の親ハーネス用に、可搬なモデルシートを 1 つ設定する。何かを探査または書き込む前に [`provider-dispatch.md`](../poteto-mode/references/provider-dispatch.md) を読む。そのモデルマトリクス、ディスクリプタ文法、ルート表が契約である。マトリクスのファミリーごとに要求エフォートを 1 つ選ぶ。2 つ目の設定ファイル、実行時リゾルバ、より弱いモデルへのフォールバックを追加してはならない。

Claude Code は `~/.claude/pstack-models.md` を書き、次の記述で `~/.claude/CLAUDE.md` から読み込む。

```text
@~/.claude/pstack-models.md
```

Codex は `~/.codex/pstack-models.md` を書く。Codex には `@` インクルードがないので、シートの正確なバイト列を `~/.codex/AGENTS.md` 内の境界付きブロック 1 つの中にミラーし、シートを編集可能な唯一の情報源として保持する。

```text
<!-- pstack:models:begin -->
<exact contents of ~/.codex/pstack-models.md>
<!-- pstack:models:end -->
```

## 手順

### 1. 親を確定する

このスキルを実行しているハーネスとツールサーフェス、つまり Claude Code または Codex を使う。環境マーカーはその最上位の答えを裏付けてもよいが、子を起動して自分がどこから来たか検出させてはならない。同じディスクリプタでもハーネスごとに異なるルートをとるので、親を記録する。

### 2. 現在の状態を読み込む

現在の親固有のシートが存在すればそれを読む。マトリクスのバリデーションの前に、以前の pstack リリースが生成したローリングエイリアスの前身だけを正規化する。プロバイダ修飾付きの Claude モデルは、そのモデル部分が `claude-fable-` または `claude-opus-` で始まり、残りのリビジョンが数字とハイフンだけで構成されるなら移行可能である。その部分をメモリ上で `fable` または `opus` に置き換え、プロバイダ、エフォート、ロール、レーンの順序を保つ。ステップ 7 の確認のために、元のディスクリプタと正規化後のディスクリプタをそれぞれ記録する。この移行は有効な読み込み済み状態であり、オペレーターによる別途の選択を必要としない。

正規化後の値を現在のロールからファミリーへの割り当てとして扱う。それらの行をステップ 7 の完全な初回ロールマップの上に重ねる。文書化されているロール行のうち欠けているものは、次に書き込みが成功したときにそのマップから実体化する。重複したロール行や未知のロール行は不整合な状態である。報告し、探査の前に解決する。古いシートに残る、プロバイダ修飾のないホストネイティブなスラッグも、どのプロバイダが所有するかを示していないので無効である。2 つの移行ファミリー以外のバージョン付き Claude モデルは不整合な状態のままである。シートが存在しなければ、完全な初回ロールマップとモデルマトリクスの Default effort セルを使う。

### 3. ファミリーごとのエフォートを解析する

モデルマトリクスを読む。エイリアス以外のすべての値は `<provider>:<model>@<effort>` に一致しなければならない。`(provider, model)` によってちょうど 1 つのマトリクスファミリーに対応づけ、そのエフォートがその行の Selectable efforts セルに現れることを要求し、エフォートを収集する。`inherit-parent` と `auto` の行はファミリーのエフォートを持たない。

一致しないプロバイダ/モデル、定義域外のエフォート、重複したロール、未知のロールは不整合な状態である。停止し、衝突する行を一字一句そのまま示し、明示的なマトリクスファミリーまたはエイリアスへの置き換えを求める。1 つ以上のファミリーでエフォートが混在していれば、衝突するすべてのファミリーとロール行を示し、ファミリーごとにその Selectable efforts セルから正規化後のエフォートを 1 つ求める。優先順位のルールをでっち上げてはならない。不整合が未解決のうちは、探査も書き込みもしてはならない。

ファミリーごとの唯一のエフォートが現在値である。エイリアス以外の出現がないファミリーは未割り当てである。そのマトリクスの Default effort を提案値として使い、現在値と呼ばずに未割り当てと表示する。

### 4. ファミリーごとに要求エフォートを 1 つ収集する

ちょうど 4 つのエフォートの質問をする。Fable、Sol、Grok、Opus にそれぞれ 1 つずつである。各モデルの名前、その現在値または提案値、そのマトリクス行の Selectable efforts を示す。空の入力は、現在値を保つか、未割り当てのファミリーについてはマトリクスの提案を受け入れる。初回実行では、質問の前に 4 つのマトリクス既定値を述べる。再実行では、カスタマイズ済みのロールレーンのリセットを持ち出さずに、解析した 4 つの値を述べる。

### 5. 要求された 4 つのペアを探査する

選択した 4 つの `provider:model@effort` ペアだけを探査する。2 つのファミリーがプロバイダを共有していても、ファミリーごとに探査を 1 回実行する。古いモデルを列挙したり、代替として提示したりしてはならない。失敗した探査は何も書かない。失敗したペアとプロバイダを報告し、停止し、現在有効なシートと親統合のバイト列を変更せずに保つ。初回実行の失敗はどちらの成果物も作らない。

| ファミリー | ペアの出所 | Claude 親のルート | Codex 親のルート | 可用性の証明 |
|---|---|---|---|---|
| Fable | Fable のマトリクス行 + 選択したエフォート | ネイティブ Agent `pstack-fable-<effort>` | Claude CLI | ネイティブの 1 ターン探査、または `claude auth status --json` と 1 ターン探査 |
| Sol | Sol のマトリクス行 + 選択したエフォート | `codex exec` | ネイティブ `spawn_agent` | `codex login status` と 1 ターン探査、またはネイティブの 1 ターン探査 |
| Grok | Grok のマトリクス行 + 選択したエフォート | Grok CLI | Grok CLI | `grok models` が要求したモデルを列挙していること。1 ターン探査 |
| Opus | Opus のマトリクス行 + 選択したエフォート | ネイティブ Agent `pstack-opus-<effort>` | Claude CLI | ネイティブの 1 ターン探査、または `claude auth status --json` と 1 ターン探査 |

一意のマーカーを返す小さな読み取り専用の探査を使う。ログイン状態コマンドだけでは認証情報は証明できるが、要求したモデルとエフォートのフラグが動くことは証明できない。ネイティブと外部の結果を別々に記録する。親自身のプロバイダに対して外部ランチャーを呼んではならない。Claude 親では、Fable と Opus の探査は対応づけられた `pstack-<stem>-<effort>` エージェントの 1 ターン実行である。Codex 親では、Sol の探査は選択した `reasoning_effort` を持つネイティブ `spawn_agent` である。他のすべてのペアは、選択したエフォートフラグを付けた外部ランナーを使う。

レシートとネイティブのトランスクリプトは、要求したエフォートとルートを証明する。プロバイダが隠している実際に適用された推論の深さは証明しない。暗黙のタイムアウト、より弱いモデルへのフォールバック、同一プロバイダの外部フォールバック、2 つ目の可変な設定ソースは存在しない。

### 6. ロールのファミリーを保ってレンダリングする

新しいシートをメモリ上に構築する。まだ書き込まない。

- 初回実行: ステップ 7 の完全なロール割り当てから始める。
- 再実行: ステップ 2 の正規化後の完全なロールマップから始め、読み込んだ各行のレーンの順序と、レーンごとのファミリー（またはエイリアス）を保つ。

エフォートの選択後、それらのロールからファミリーへの割り当てを保つか、名指ししたロールを変えるかを尋ねる。保つのが既定である。オペレーターが名指ししたロールの変更だけを適用する。カスタマイズ済みのシートを初回割り当てへリセットすることは決して持ち出さない。変更されたロールは、探査済みの 4 つのマトリクスファミリーのいずれか、`inherit-parent`、または `auto` を使える。

最終的なロールマップには、各マトリクスファミリーのディスクリプタが少なくとも 1 つ含まれることを要求する。シートはエフォートをロールディスクリプタの中にだけ保存するので、未割り当てのファミリーの選択は、2 つ目の情報源を追加しなければ永続化できない。

すべてのマトリクスファミリーのディスクリプタを `provider:model@<requested effort for that family>` に書き換える。`inherit-parent` と `auto` はそのまま残す。エフォートだけの再実行はロールのファミリーを変えられない。Grok のエフォートを変えると Grok のすべての出現が更新されるが、Sol のロールが Grok へ移ることはない。修飾のないスラッグ、利用できないルート、4 つのマトリクスファミリー以外のモデル、プロバイダ/モデルの不一致は拒否する。

### 7. 確認してコミットする

ローリングエイリアスの移行があれば、元のディスクリプタと正規化後のディスクリプタとして示す。次に、この親のルート表と、レンダリングしたすべてのロールとディスクリプタを示す。書き込む前に確認を求める。

Why と Reflect は親のライブな MCP サーフェスを必要とする。それらの調査役、レビュアー、シンセサイザー（統合役）のロールは `inherit-parent` または `auto` に保つ。境界付きの外部ランナーは意図的に環境に備わる MCP を省いている。`inherit-parent` と `auto` は常にバリデーションを通るが、パネルのプロバイダ多様性を下げる場合はそう伝える。パネルのロールでは、エントリごとに 1 レーンが動く。リストの長さがファンアウト数である。`arena cross-judge pool` は、Arena が可能なときに親およびベース候補と異なるプロバイダを選ぶためのリストである。`swarm workers` は、レースが明示的に別のディスクリプタを割り当てない限り、すべてのワーカーの既定である。

エイリアス以外のすべての値は `<provider>:<model>@<effort>` に一致し、かつステップ 5 を通過していなければならない。

オペレーターが確認した後、ステップ 6 のメモリ上のレンダリングを書き込む。下の例を結果としてそのまま貼り付けてはならない。それはステップ 2 の種となる完全な初回ロールマップにすぎない。書き込みの前には、選択したエフォートと明示的なロール変更が常にその例の値を置き換える。

```markdown
# pstack model configuration

Provider-qualified per-role choices. Read the installed pstack provider-dispatch reference before dispatching a configured role. Every documented role remains present. `inherit-parent` and `auto` use the parent model natively and still count as one panel lane.

feature, refactoring: grok:grok-4.6@xhigh
bug-fix: codex:gpt-5.6-sol@max
perf-issue: codex:gpt-5.6-sol@max
hillclimb: codex:gpt-5.6-sol@max
judgment and prose: claude:fable@max
hardest tasks: claude:fable@max
how explorer: grok:grok-4.6@xhigh
how explainer: claude:fable@max
why investigators, synthesizer: inherit-parent
reflect tooling, judgment, divergent, synthesizer: inherit-parent
arena runners: claude:fable@max, codex:gpt-5.6-sol@max, grok:grok-4.6@xhigh, claude:opus@xhigh
arena cross-judge pool: claude:fable@max, codex:gpt-5.6-sol@max, grok:grok-4.6@xhigh, claude:opus@xhigh
swarm workers: grok:grok-4.6@xhigh
architect runners: claude:fable@max, codex:gpt-5.6-sol@max, grok:grok-4.6@xhigh, claude:opus@xhigh
interrogate reviewers: claude:fable@max, codex:gpt-5.6-sol@max, grok:grok-4.6@xhigh, claude:opus@xhigh
```

### 8. 組み込む

どちらの書き込みよりも前に、親統合をメモリ上にレンダリングする。Claude では、統合は `~/.claude/CLAUDE.md` 内の単一の `@~/.claude/pstack-models.md` インクルードである。Codex では、`~/.codex/AGENTS.md` 内の 1 組の `<!-- pstack:models:begin -->` と `<!-- pstack:models:end -->` の間にあるシートの正確なバイト列である。再実行では、その境界付きブロック全体を置き換える。初回実行では、末尾にブロックを 1 つ挿入する。いずれかのマーカーが欠けている、重複している、または順序が逆なら、境界を推測せずに停止して不整合な状態を報告する。

すべての対象の現在のバイト列をスナップショットする。4 つの探査がすべて通り、オペレーターが確認した後にだけ、シートと親統合を書き込む。両方の対象を読み戻し、メモリ上のレンダリングと比較する。書き込みまたは読み戻しのいずれかが失敗したら、すべてのスナップショットを復元して失敗を報告する。変更のない再実行は、正規化後にバイト単位で同一のシートと統合内容を生成しなければならない。

親固有の探査を再実行せずに、ハーネス間でモデルシートをコピーしてはならない。同じホスト上でもルートの可用性は異なりうる。

### 9. 挙動のスモーク

セットアップ完了を宣言する前に、この親から小さな読み取り専用の混成パネルを 1 回実行する。選択した 4 つのディスクリプタすべて、別々の出力/レシートパス、独立したクロスジャッジを使う。Claude ネイティブのエージェントとすべての外部プロセスを、ハンドルを保持したままバックグラウンドで起動し、その後それらを回収する。ネイティブのトランスクリプトエントリとすべての外部レシートを検証する。構造的な設定チェックや単体テストは代わりにならない。

シートのパス、親のルート表、要求エフォートの探査結果、スモーク結果、外部の経過時間/トークン/コストのレシートを報告する。このスキルを再実行すると、再探査して同じシートを更新する。プロバイダが隠している実際に適用されたエフォートの観測可能性を公開したと主張してはならない。
