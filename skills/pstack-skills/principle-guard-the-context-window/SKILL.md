# Guard the Context Window

コンテキストウィンドウはセッション内で有限であり、補充できない。すべてのトークンはそのコストに値するべきである。

**理由:** コンテキストのオーバーフローは推論の質を低下させ、圧縮による歪みを生み、進行を止める。

**パターン:**
- **大きなペイロードを分離する。** 冗長な出力、スクリーンショット、大きな文書はサブエージェントにルーティングする。メインのコンテキストには生データではなく要約を渡す。
- **使わないものを読まない。** 関連性に基づいて選択的に読む。現在のタスクにファイルが必要でなければ、飛ばす。
- **頻繁に使う内容はインラインに保つ。** 毎回の呼び出しで使うテンプレートや参照はスキルファイルに置く。呼び出すたびに読み取りのコストがかかる別ファイルには置かない。
- **フェーズの大きさを決め、範囲に上限を設ける。** フェーズごとのファイル数を制限し、ターン予算を設定し、仕組みのコストを織り込む。
