# フリーランスエンジニアの面談準備資料を作る

企業が求める役割と職務経歴書の実績を結び付け、面談でそのまま話せる自己紹介と想定問答を作る。

## 子スキル

各工程を始める直前に、対応する `SKILL.md` を最後まで読む。

- `quality-gated-review-improve`
- `natural-japanese-rewriter`
- `bullet-list-rewriter`
- `sentence-linebreak`

子スキルが見つからない場合はその工程を省略せず、見つからないスキル名を報告して停止する。

## 入力と出力を確定する

`$ARGUMENTS` は次の JavaScript オブジェクト形式で受け取る。

```javascript
{
  my_skill_data: "path/to/my/skill/data",
  input_corp_data: "path/to/my/corp/data",
  output_dir: "path/to/my/output/dir"
}
```

各キーは必須とし、次の役割で扱う。

- `my_skill_data`: 本人のスキル、職務経歴、実績を含むファイルまたはディレクトリ
- `input_corp_data`: 企業、募集、案件に関する情報を含むファイルまたはディレクトリ
- `output_dir`: `mendan-junbi.adoc` を保存するディレクトリ

相対パスは現在の作業ディレクトリを基準に解決する。
2つの入力パスがファイルならそのファイルを読み、ディレクトリなら配下の通常ファイルを再帰的に読む。
オブジェクトを解釈できない、必須キーがない、入力パスが存在しない、または入力データが空の場合は、出力を作らず問題を報告する。

既存の入力ファイルは変更しない。
`output_dir` がなければ作成する。
出力先は `<output_dir>/mendan-junbi.adoc` とする。
出力ファイルがある場合は草稿として読み、今回確認した情報で自己紹介と想定問答を更新する。

## PDF を Markdown へ変換する

`my_skill_data` がディレクトリの場合は、配下の `.pdf` ファイルを再帰的に探す。
`git rev-parse --show-toplevel` で現在のリポジトリ直下を特定する。
PDF があり、リポジトリ直下の `Justfile` に `pdf-to-markdown` レシピがある場合は、面談準備資料の生成前にすべての PDF を Markdown へ変換する。

リポジトリ直下で `just --show pdf-to-markdown` または `Justfile` を確認し、レシピの引数と出力先を特定してから、その定義どおりに実行する。
引数や出力先を推測しない。
レシピがディレクトリを受け取る場合は `my_skill_data` を渡し、PDFごとのパスを受け取る場合は各PDFへ実行する。

変換コマンドがすべて成功し、各PDFに対応する空でないMarkdownが生成されたことを確認する。
以後は変換後のMarkdownを職務経歴データとして読み、同じPDFを重複して解析しない。
変換に失敗した場合、または対応するMarkdownを確認できない場合は、`mendan-junbi.adoc` を生成せず停止し、失敗したPDFとコマンド結果を報告する。
`pdf-to-markdown` レシピがない場合は、この前処理を省略する。

## 企業と経歴の接点を整理する

企業情報から、事業、募集する役割、必須条件、歓迎条件、技術、課題、期待する成果を抽出する。
職務経歴書から、経験、実績、技術、担当範囲、役割、仕事の進め方を抽出する。

企業の期待ごとに、職務経歴書で確認できる根拠、アピールできる強み、不足する経験を対応付ける。
事実、合理的な推測、未確認事項を分ける。
職務経歴書にない経験、役割、成果、数値は作らない。
不足する経験は、近い経験と学習方法を示し、経験済みとは書かない。

## 自己紹介を書く

声に出して3〜5分で話せる自然な日本語にする。
1分あたり約300字を目安に、本文を900〜1500字にする。
事実が足りず900字に届かない場合は、水増しせず短いまま書く。
字数は ` +`、改行、`[要確認: …]` を除き、コマンドで数える。
次の基本要素を、この順で一続きの自己紹介としてまとめる。

1. エンジニア歴と主なポジション
2. 簡単な職歴
3. 得意な言語や領域と、企業の期待に合う強み
4. 直近の案件の概要
5. 志望理由

エンジニア歴は、職務経歴書に明記された年数を使う。
明記がなければ、最も古い開発経験の開始年月から実行日までを年単位で数え、端数は切り捨てる。
職務経歴書の時系列を読み上げず、職歴は数文に要約する。
企業との接点が強い経験を優先する。
抽象的な長所だけで終えず、担当したこと、判断したこと、確認できる結果を使う。
志望理由では、単価、稼働日数、リモート可否などの契約条件に触れない。
企業情報の事業、プロダクト、技術、課題のうち、職務経歴書の経験や入力に書かれた関心と結び付く点を、興味を持った理由として挙げる。
企業情報に事業やプロダクトの説明がない場合は技術との接点で書き、`[要確認: 事業やプロダクトで興味を持った点]` を添える。
志望理由は、今回の企業または案件で貢献できることで締める。
入力で確認できない要素は推測で埋めず、`[要確認: 確認する内容]` と書く。

## 想定問答を書く

企業情報と職務経歴書から、面談で確認される可能性が高い質問を選ぶ。
応募理由、関連経験、技術選定、問題解決、チームでの役割、企業が求める技術との差を優先し、重複する質問はまとめる。
質問数を満たすための水増しはしない。

各回答は、基本的に声に出して90秒以内で話せる長さにする。
回答は結論から書き、具体例と企業での活用方法を続ける。
実績の回答では、状況、担当した行動、結果が分かるようにする。
技術判断の回答では、選択肢、採用理由、制約または欠点を示す。
必要な事実が入力にない場合は、推測で埋めず `[要確認: 確認する内容]` と書く。

## AsciiDoc を保存する

次の構造で、1件の AsciiDoc ファイルとして保存する。

```asciidoc
= 面談準備
:toc:
:sectnums:

== 自己紹介

自己紹介の本文

== 想定問答

=== Q1. 質問

回答::
回答の本文
```

Markdown の記法を混ぜない。
自己紹介と想定問答の両方に本文があることを確認する。
出力を再読し、各主張が入力ファイルの事実と一致し、企業の期待と職務経歴書の接点が伝わることを確認する。

## 出力を仕上げる

`<output_dir>/mendan-junbi.adoc` を作成した後、次の順序で同じファイルを更新する。
`my_skill_data` と `input_corp_data` は読み取り専用の根拠として使い、変更しない。

1. `quality-gated-review-improve` を実行する。
   改善対象を `<output_dir>/mendan-junbi.adoc`、根拠資料を `my_skill_data` と `input_corp_data` として渡す。
   企業への訴求、経歴との整合、回答の具体性、自己紹介の基本要素とその順序、最後の志望理由、話せる長さ（自己紹介は「自己紹介を書く」の字数規則、回答は90秒以内）、AsciiDocの構造を採点対象に加える。
   字数規則は、900字未満を許す条件と数え方も含めて具体的な値で渡す。
   入力にない事実を追加せず、最良版を同じファイルへ反映する。
2. `natural-japanese-rewriter` を、第一引数を `safe` にして実行する。
   品質ゲート後のファイルを対象に、事実、意味、`[要確認]`、AsciiDocの構造、自己紹介の基本要素の順序、話せる長さの制約を保ったまま、口頭で話しやすい自然な日本語へ直す。
3. `bullet-list-rewriter` を実行する。
   日本語推敲後のファイルを対象に、列挙、条件、手順、比較などの並列情報だけをAsciiDocの箇条書きへ直す。
   自己紹介は箇条書きにしない。
   回答本文は、長いという理由だけで箇条書きにしない。
4. `sentence-linebreak` を実行する。
   箇条書き整理後のファイルを対象に、通常の文章を一文ごとの物理行へ分け、各文末へAsciiDocの改行記号 ` +` を付ける。
   見出し、属性行、コードブロック、表、箇条書きなどの構造を保ち、HTMLへ変換したときに一文ごとに改行されるAsciiDocへ更新する。

仕上げ後のファイルを再読する。
すべての主張が根拠資料と一致し、自己紹介と想定問答の構造が保たれていることを確認する。
自己紹介が基本要素を順に含み、「自己紹介を書く」の字数規則に収まり、志望理由で終わることを確認する。
各回答が基本的に90秒以内で話せる長さであることも確認する。
通常の文章が一文ごとに改行され、構造要素へ不要な改行記号が追加されていないことも確認する。
満たさない箇所は根拠資料の範囲で直し、一文ごとの改行を保つ。

完了時に、出力ファイルのパス、参照した入力ファイル、品質ゲートの最終点、残った `[要確認]` を報告する。
